# Клиент FFIDO

Требуется Flutter 3.47.7 / Dart 3.13.5. Перед выполнением команд выберите этот
SDK в PATH (`export PATH="/path/to/flutter-3.47.7/bin:$PATH"`). CI использует ту же
закреплённую версию; общий SDK других проектов менять не требуется.

Flutter-клиент использует контракт `contracts/ffido/v1/ffido.proto`. Android, iOS,
Windows, Linux и macOS обращаются к TLS gRPC; Web — к HTTPS gRPC-Web шлюзу.
REST-клиент удалён. Версии runtime и генератора закреплены в `pubspec.yaml`
и `tools/proto/generate.sh`.

Из каталога `apps/frontend`:

```sh
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
flutter build web --release --no-pub
flutter run --dart-define=FFIDO_ENDPOINT=https://localhost:8080
```

Для Web указывайте HTTPS адрес шлюза, например порт 8443. Сертификат должен
быть доверенным для ОС/браузера; приложение не отключает проверку TLS.
В форме подключения укажите имя, FTN-адрес, пароль линка HPT и HTTPS-адрес
сервера FFIDO. Проверяется SessionPwd, при его отсутствии Password. Первый вход
создаёт профиль; последующие используют имя, уже сохранённое на сервере.
Пароль HPT не сохраняется. Android и настольные клиенты сохраняют внутреннюю
сессию в системном защищённом хранилище (на macOS — login Keychain); если оно недоступно, приложение явно
сообщает, что после перезапуска потребуется пароль. Для Linux нужны libsecret
и работающая служба системного хранилища. В Web вход действует только в памяти
до закрытия приложения. SharedPreferences хранит только несекретные настройки,
признаки отключения автовхода и ограниченный кеш конференций.

Для телефона и ноутбука используйте одинаковые адрес сервера и FTN-адрес.
Оба устройства имеют отдельные сессии и общие профиль, прочитанность, историю
и закладки. При возврате из фона и обновлении загружается серверное состояние.
Отправленное на телефоне письмо появится на ноутбуке после обновления; доставка
в FTN зависит от HPT и мейлера. Черновики и прокрутка не синхронизируются.
Выход на одном устройстве не отключает другое. Сессия действует 30 суток.

Конференции, сообщения, цепочки, профиль, закладки и история загружаются через
RPC. Чтение записывает личную прочитанность и историю на сервере; JAM .jlr
не меняется. Пагинация учитывает серверный `has_more`. Ответ адресован автору
исходного сообщения; в эхоконференции его видят все участники.

Подтверждение отправки означает **«сохранено локально»**. При потере ответа
форма сохраняет текст и operation_id и предлагает явный повтор. Повтор с тем
же идентификатором и текстом не добавляет второе сообщение. Поля блокируются
при неопределённом результате, чтобы не изменить содержание повторяемой
операции. Смена сервера или сессии отменяет RPC и удаляет данные старой сессии.
Незавершённая форма не переживает закрытие приложения.

Главный список сначала показывает личную почту (NetmailArea), затем LocalArea,
BadArea, DupeArea и RobotsArea. Далее идут эхи с непрочитанными сообщениями,
затем остальные эхи; внутри каждого типа и обеих групп эх действует алфавитный
порядок отображаемого имени без учёта регистра (при равенстве — по ID).
Неизвестная статистика не считается положительным числом непрочитанных.
Для правильного порядка клиент сначала загружает все страницы текущего поиска
и только затем показывает результат. После чтения и массовой отметки порядок
обновляется с сохранением поиска. На больших каталогах первоначальная загрузка
требует нескольких последовательных запросов. API не предоставляет снимок
каталога между страницами: при параллельных изменениях повторное обновление
может потребоваться для получения всех добавленных областей.

В закладках рядом с каждой эхой показано количество непрочитанных, включая 0.
Если статистика неизвестна, отображается «—» с пояснением. Счётчики обновляются
после чтения, открытия вкладки и ручного обновления. Порядок закладок и истории
сохраняется; кнопка удаления остаётся рядом со счётчиком.

Кешируется только первая страница общего списка конференций на пять минут,
с учётом endpoint, session epoch, schema и limit. Поиск и следующие страницы
не кешируются. Fallback возможен лишь при UNAVAILABLE/DEADLINE_EXCEEDED;
ошибки авторизации, проверки полей и повреждения базы не скрываются кешем.
Главный список всегда начинает с сетевой загрузки и не смешивает кешированную
страницу с сетевыми. После успешной загрузки сохраняется только первая страница
каталога без приватных областей. При недоступности первого запроса допустим
прежний кеш; если он неполный, над списком явно показаны отметка неполноты и
кнопка повтора. Ошибка последующей страницы показывает ошибку с повтором вместо
нового частичного результата. При запуске старые кеши удаляются.

Тесты используют внедряемый typed transport; тесты самого ApiClient выполняют
настоящие RPC к изолированному тестовому серверу. Generated-код не форматируют
и не редактируют вручную: запускайте `tools/proto/generate.sh` из корня.

Нативные release-сборки выполняйте штатными командами `flutter build apk --release`
и `flutter build macos --release`. После integration_test не добавляйте
`--no-pub`: установленный Flutter должен заново сгенерировать регистрацию
production-плагинов. Проверка двух клиентов и настоящих системных хранилищ:
`python3 scripts/check_two_devices.py --android emulator-5554` из корня проекта
при уже запущенном эмуляторе. Прогон использует временные данные и отдельный
тестовый CA, не отключая проверку TLS.

### Права на эхи

Клиент использует `can_read` и `can_post`, полученные от FFIDO по настройкам
линка HPT. В режиме только чтения нет создания и ответа; в режиме только
постинга доступно новое сообщение без списка писем и счётчиков.
Сервер проверяет права каждого запроса. Отказ доступа очищает показанные
сообщения и кеш каталога, но сохраняет текст неотправленного сообщения.
Обновляйте клиент и сервер вместе: отсутствие новых полей не даёт разрешений.
До ответа сервера при недоступной сети может использоваться прежний ограниченный
кеш каталога; мгновенного удаления данных на отключённом устройстве нет.

### Независимые профили macOS

Один release bundle можно запустить с разными профилями:

```sh
open -n build/macos/Build/Products/Release/fido.app --args --profile point1
open -n build/macos/Build/Products/Release/fido.app --args --profile point2
```

Перед первой проверкой закройте старые экземпляры приложения, сохранив черновики.
Каждый новый профиль требует первого входа; затем независимо запоминает сервер,
имя, FTN-адрес, настройки и сессию в Keychain. Оба могут использовать один и тот же
адрес сервера. Пароль не сохраняется. Допустимы 1–32 строчных латинских букв,
цифр, `_` и `-`, начиная с буквы или цифры; также допустим `--profile=point1`.
Один профиль одновременно открывается только в одном процессе; после закрытия
или аварийного завершения блокировка освобождается автоматически.

Запуск без аргумента или с `--profile default` использует прежние настройки и вход.
Именованные профили не копируют legacy-аккаунт. Их настройки и кеш имеют отдельные
prefixes, ключи сессий также раздельные; выход/смена сервера не затрагивают соседнее окно.
Истёкшая/отозванная сессия требует нового входа, а недоступная сеть не заменяет аккаунт.

Заголовок после входа: `FFIDO — Demo Point 1 (2:1/2.1) [point1]`.
Имя и адрес относятся к вошедшему FTN-аккаунту и берутся из ответа сервера.
Без авторизации: `FFIDO [point1]`. Пароль и секрет сессии в заголовок не передаются.
macOS может попросить разрешить приложению доступ к связке ключей.

Для проверки на временном стенде подключите два профиля к одному endpoint разными
поинтами, отправьте письмо и ответ, закройте и вновь запустите теми же командами.
Проверьте восстановление аккаунтов/заголовков и независимый выход. При rollback
старая сборка продолжит читать только default, именованные данные останутся для
возврата новой версии; автоматического переноса или удаления секретов нет.

Нативные проверки аргументов и lease из корня репозитория:

```sh
swiftc apps/frontend/macos/Runner/LaunchProfile.swift apps/frontend/test/native/profile_test.swift -o /tmp/ffido-profile-native-test
/tmp/ffido-profile-native-test
```

### Прочитать всю эху и навигация

В читаемой EchoArea откройте меню «Действия эхи» → «Отметить всё прочитанным».
Подтверждение относится ко всей эхе, включая другие страницы и цепочки.
Изменяются только серверные отметки текущего пользователя; история просмотра и
последнее открытое письмо не перемещаются. Netmail и служебные области не имеют
этого действия. Другие устройства увидят результат при refresh/resume.

При потере ответа выберите «Проверить/повторить»: пока экран открыт, повтор использует
тот же ключ и не захватывает новые письма. Неопределённый результат не обозначается
успехом. Закрытие экрана не отменяет уже выполненную серверную транзакцию; новое
явное действие после повторного открытия — новая операция с новым снимком.
Старый сервер показывает сообщение о неподдерживаемой массовой отметке.

Четыре раздела нижней панели отображаются иконками без постоянных подписей:
дом, закладка, история, профиль. Названия доступны в подсказках и для экранного
диктора; активный раздел выделен цветом и формой/индикатором. Кнопки перехода
между письмами остаются отдельными от этой панели.

## Обновления приложения

Кнопка «Обновления приложения» на экранах подключения и конференций открывает
текущую версию, канал stable/dev и ручную проверку. Проверка не требует входа
на сервер. После запуска и при возвращении в приложение (не чаще раза в 6 часов)
новый совместимый подписанный выпуск вызывает немодальное уведомление с кнопками
«Обновить» и «Позже». «Позже» скрывает уведомление до следующего запуска;
обновление остаётся доступно на отдельном экране.

Загрузка начинается после нажатия «Обновить», показывается прогресс. Ошибки можно
повторить; фоновая ошибка не прерывает чтение. Открытый редактор сообщения блокирует
переход к установке: сначала завершите отправку и сохраните нужный текст, затем
закройте редактор. Updater не закрывает его принудительно.

Первый клиент с updater нужно установить вручную. Локальные `-check.` сборки и
сборки без доверенного ключа не предлагают автоматическую установку. В CI
`scripts/release/build_identity.py` переносит identity и публичные trust anchors
в assets; исходный приватный ключ в приложение не включается. Выбор канала не
разрешает понижение версии; Android также требует большего build number.

На Android установка подтверждается штатным установщиком, при необходимости
ОС запрашивает разрешение установки из этого приложения. На macOS сохраняется
ad-hoc подпись: после обновления допустим системный запрос доступа к Keychain
или повторный вход. Настройки профиля сохраняются; токены не переносятся из
Keychain в preferences или обычные файлы.

Windows/Linux используют отдельный `ffido-updater`, упакованный как самостоятельный
исполняемый файл: Python пользователю не требуется. Обновляйте portable-установки
в принадлежащем вам закрытом родительском каталоге (например, `~/Applications/FFIDO`),
сохраняя весь комплект файлов. Все окна должны завершиться перед заменой; helper
ожидает освобождения общей блокировки. Предыдущий комплект сохраняется в соседнем
`<каталог>.previous` до подтверждения запуска нового клиента. При ошибке запуска
восстанавливается прежний комплект. Установки без прав записи требуют действий
оператора; updater не повышает привилегии автоматически.

### Кросспостинг текстового сообщения

В редакторе нового письма, ответа или пересылки в эху откройте «⋯» →
«Кросспостинг». Найдите нужные эхи и отметьте дополнительные назначения
галочками, затем нажмите «Готово». Исходная эха обязательна; выбрать можно
до 20 дополнительных доступных для публикации эх. Выбор сохраняется при
поиске и переходе между страницами, закрытие списка без подтверждения
отменяет изменения. Снятие всех галочек возвращает обычную отправку.

Редактор показывает неизменяемый предпросмотр блока GoldED+:
`* Originally in …` и по одной строке `* Crossposted in …`. Сервер добавляет
его перед пользовательским текстом во все копии. UUE-вложение и кросспостинг
взаимоисключающие: сначала снимите выбор эх или уберите файл.

При частичном или неизвестном результате текст и назначения замораживаются.
«Повторить отправку» продолжает ту же серверную группу без дублей. Закрытие
редактора предупреждает, что часть копий могла сохраниться; черновик не
восстанавливается после перезапуска приложения. Успех означает локальное
сохранение всех копий, а не доставку по FidoNet.

Требуется сервер с CreateCrosspost. При UNIMPLEMENTED клиент сохраняет данные
в открытом редакторе и сообщает о необходимости обновления сервера; автоматической
замены на одиночную отправку нет. Общий контракт генерируется штатным
`tools/proto/generate.sh` без изменения версий зависимостей.

### Отказ установки Android и диагностика

Если Android запрещает обновление, FFIDO сохраняет текущую установку и показывает
доступный результат: отмена, отсутствие разрешения, системный запрет или ошибка.
Системный запрет сам по себе не определяет, какая служба его вызвала. Не отключайте
Play Защиту ради обновления. При неизвестном результате проверьте установленную
версию; приложение не запускает установку повторно автоматически.

В разделе «Обновления FFIDO» кнопка «Диагностика обновления» открывает выделяемый
текст: текущая и целевая версии/build, канал, публичный URL и SHA-256 пакета,
доступный исход/числовой код Android. При пересоздании приложения восстанавливаются
сохранённые публичные сведения и доступный результат системной сессии. Сводка не
содержит пароли, сессионные токены, сообщения или приватные пути и не отправляется
автоматически. Её можно передать разработчику по своему решению вместе с текстом
предупреждения и моделью/версией Android.

### Tagline и Origin

В настройках отдельный раздел «Оформление исходящих сообщений» позволяет сохранить
Tagline (текст после `---`) и Origin без переподключения. По умолчанию используются
`FFIDO <версия клиента>` и `https://github.com/hashev/ffido`. Пустое поле или
«Сбросить оформление» возвращает автоматическое значение; пользовательские значения
сохраняются при обновлении. Настройки изолированы существующим профилем клиента.

Нужен обновлённый сервер с поддержкой оформления в Login/RestoreSession. На старом
сервере остаётся обычная отправка с прежним footer; при пользовательском override
клиент объясняет необходимость обновить сервер или сбросить оформление до отправки.
Это сохраняет черновик и исключает тихое игнорирование выбора. В Origin сервер сам
добавляет подтверждённый FTN-адрес. Настройки относятся к эховым письмам, включая
ответы, пересылку, кросспостинг и UUE; netmail/local не получают эховый footer.

Допускается одна строка до 256 UTF-8 байт без управляющих символов. Сервер дополнительно
проверяет кодируемость и размер письма. Оформление фиксируется при первой попытке
операции: изменение настроек не меняет незавершённую отправку или частичный кросспост.

### Ссылки и изображения в письмах

В режиме чтения HTTP/HTTPS и `www.` выделяются подчёркнутым цветом ссылки.
Нажатие открывает внешний браузер (`www.` получает HTTPS); на компьютере
доступны мышь, Tab и Enter/Space. Исходные символы, отступы, цитаты,
выделение и копирование сохраняются. Редактор и кодированные UUE-блоки
не открывают ссылки. URL с userinfo, локальные и исполняемые схемы не запускаются.

Прямые PNG/JPEG/GIF/WebP автоматически получают preview, в том числе URL
без расширения: формат проверяется по ответу и байтам. HTML-страницы,
Open Graph и SVG не поддерживаются. GIF/WebP показывают первый кадр.
При чтении клиент обращается к внешним сайтам: первые 10 уникальных URL,
не более двух одновременно, следующие — по кнопке «Загрузить ещё изображения».
HEAD исключает явно неподходящие страницы; ограниченный GET распознаёт
изображения. FFIDO-токены, cookies сессии и собственные доверенные
сертификаты не используются. TLS, CORS и mixed-content ограничения не обходятся;
браузер может запретить проверку редиректа. При ошибке исходная ссылка остаётся
доступной, предусмотрен ручной повтор без автоматического открытия браузера.

Лимиты: 16 МиБ на файл, 16 миллионов пикселей, 8192 пикселя по стороне,
3 перенаправления, 15 секунд на загрузку; неизвестный формат проверяется
в пределах 64 КиБ. Thumbnail вписан в 1000×1000, кеш исходников текущего
письма ограничен 32 МиБ (LRU). Вытесненное изображение можно загрузить повторно.
Уход из письма или смена сессии отменяет загрузки и очищает память.

Нажатие preview открывает полноэкранный просмотр с zoom/pan; кнопка закрытия,
Back и Escape возвращают к письму. Просмотр и отправка используют уже
проверенные байты без повторного GET. Доступно сохранение файла.

| Платформа | Передача изображения |
|---|---|
| Android | Системное «Поделиться», файл через закрытый FileProvider, только временное чтение |
| macOS / Windows / iOS | Системная отправка файла, если доступна; иначе сохранение |
| Linux | Сохранение файла |
| Web | Web Share файла при поддержке браузера; иначе явное сохранение/download |

Отмена не считается успешной отправкой. Открытие системного диалога не
подтверждает доставку в другое приложение. Временные native share-файлы
приватны; просроченные очищаются по TTL 24 часа. Android сохраняет каждую
отправку отдельно и не удаляет предыдущий файл при следующей отправке.
Широкий доступ к хранилищу и разрешение на запись получателю не нужны.
Фактическая матрица приёмки и ограничения среды — в `../../docs/testing.md`.
