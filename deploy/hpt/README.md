# Локальная политика HPT на amster2

Это дополнение для внешнего HPT worker, а не часть официального образа FFIDO.
Оно соответствует локальным JAM узла: обычные эхи KOI8-R, область `utf-8` UTF-8.
Включение для другого набора кодировок исказит сообщения.

`build-hpt.sh` собирает закреплённые Husky-зависимости в `/opt/ffido-hpt`
и применяет `hpt-transport.patch` с `git apply --check` к HPT
`c2a91d64cee0e6cd357376d30c9285ee3f9c624f`. Для Dockerfile worker:

```dockerfile
COPY build-hpt.sh hpt-transport.patch /opt/ffido-local/
RUN sh /opt/ffido-local/build-hpt.sh
ENV FFIDO_HPT_KOI8_CP866=1
```

При включённой политике HPT использует существующий KOI8-R → CP866 `outtab`
для обычных эх и формирует один `CHRS: CP866 2` в экспортируемой копии.
Для `utf-8` (регистр имени незначим) обходит `outtab`, формирует
`CHRS: UTF-8 4` и обходит входящий `intab` при записи в эту JAM.
Для обычных эх требуются `RecodeMsgBase on` и обе таблицы. Если они отсутствуют,
отключены либо загрузчик таблиц возвращает ошибку, HPT завершает запуск с
ошибкой конфигурации до обработки сообщений.
Без переменной со значением `1` поведение upstream сохраняется.
Правила netmail, подписки HPT и исторические JAM не меняются.
Существующая нормализация исходящего текста FFIDO также сохраняется.

На amster2 файлы устанавливаются в `/home/yurik/fido/ffido/ops`;
сборка — `docker compose build ffido-tosser` из `/home/yurik/fido`.
Перед заменой запущенного worker обязательны согласованная резервная копия,
проверка на изолированных базах и остановка действующего worker до конца его цикла.
Не запускайте raw HPT параллельно координированному `ffido-run-hpt`.
При смене upstream повторите проверку; не удаляйте patch ради успешной сборки.

Проверочный сценарий `verify-amster2.py` запускается Python-окружением VPS с grpcio
и сгенерированными модулями FFIDO в `ffido/probe`. Нужны локальные образы FFIDO,
нового worker и контрольного worker до исправления, а также TLS-файлы узла.
Сценарий не изменяет рабочие базы, очереди и конфигурацию: он создаёт отдельные
JAM в `ffido/verification/hpt-charset`, поднимает временный FFIDO на localhost:18082,
отправляет сообщения только в эти JAM и запускает HPT с `--network none`.
Порт и имя временного контейнера должны быть свободны.

```sh
cd /home/yurik/fido
ffido/venv/bin/python ffido/ops/verify-amster2.py \
  --image ffido:encoding-review-local-20261023 \
  --worker ffido-tosser:local \
  --control-worker ffido-tosser:before-hpt-transport-20261023
```

Проверяются публикация и ответ через API → локальная JAM → HPT scan → PKT →
HPT toss второго узла → чтение API. Независимый декодер проверяет байты тела,
темы, имён и CHRS, reply-связь и отсутствие повторного экспорта. Прежний HPT
и новая сборка без включения политики должны воспроизводить исходную ошибку.
Исторические испорченные UTF-8 записи этот сценарий не исправляет.

Подготовка обновления FFIDO, текущая блокировка схемы и восстановление описаны
в [инструкции обновления amster2](ffido-upgrade.md).
