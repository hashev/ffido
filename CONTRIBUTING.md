# Участие в FFIDO

Исходники и Releases публичны. Создавать PR в upstream и публиковать рабочие
ветки могут только приглашённые владельцем участники. Получение приглашения
не требуется для скачивания и использования кода на условиях MIT.

1. Создайте рабочую ветку, например `codex/fix-description`.
2. Следуйте `AGENTS.md`; используйте общий OpenSpec в корне для планируемых изменений.
3. Выполните проверки из README. Не добавляйте локальные конфиги, базы и ключи.
4. Создайте PR в `master`. Все обязательные jobs должны пройти, включая нативную
   матрицу и HPT-тесты. Не заменяйте отсутствующую среду зелёным skipped result.
5. Сливайте squash merge после `ci-required` и разрешения обсуждений. Второе
   approval не обязательно; владелец может слить собственный PR.

Не пушьте напрямую в master, не обходите защиту и не переписывайте выпущенные теги.
Отладочная подпись Android допустима только для непубликуемых CI-сборок.
Рабочая нода amster2 не является тестовым runner и не меняется pipeline.

Автоматизация, экспорт и первая загрузка: [docs/github-publication.md](docs/github-publication.md).
