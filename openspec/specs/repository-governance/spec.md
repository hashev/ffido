# repository-governance Specification

## Purpose

Определяет публичную доступность FFIDO и управляемый порядок внесения изменений приглашёнными участниками через защищённую основную ветку.

## Requirements

### Requirement: Публичное получение и управляемое участие
Репозиторий SHALL предоставлять публичное получение исходников и опубликованных пакетов без приглашения. Создание PR SHALL быть разрешено только явно приглашённым участникам с необходимыми правами. Права записи SHALL не выдаваться посторонним автоматически.

#### Scenario: Посетитель без прав
- **WHEN** посетитель без приглашения открывает репозиторий
- **THEN** он может получить исходники и пакеты, но не может отправить PR или записать изменения в репозиторий

#### Scenario: Приглашённый участник
- **WHEN** владелец выдаёт участнику право записи
- **THEN** участник может публиковать рабочие ветки и создавать PR в master

### Requirement: Обязательный PR в основную ветку
После начальной настройки обновление `master` SHALL требовать PR и успешных обязательных проверок актуального изменения. Прямой push, force push и удаление master SHALL блокироваться, включая владельца без исключения обхода. Обязательное одобрение второго участника SHALL не требоваться.

#### Scenario: Собственное изменение владельца
- **WHEN** владелец создаёт PR и обязательный CI успешно завершается
- **THEN** он может слить свой PR самостоятельно

#### Scenario: Ошибка проверки
- **WHEN** хотя бы одна обязательная проверка падает или не завершается
- **THEN** PR не может быть слит и не создаёт публичный релиз

#### Scenario: Обход PR
- **WHEN** участник или владелец пытается напрямую обновить или удалить master после настройки защиты
- **THEN** сервер GitHub отклоняет операцию

### Requirement: Проверяемая инструкция настройки
Руководство SHALL описывать создание репозитория, начальную загрузку, приглашения, включение защиты, регистрацию обязательных проверок и проверку запретов. Начальное создание master SHALL быть явно отделено от последующих изменений через PR.

#### Scenario: Первая публикация
- **WHEN** владелец выполняет руководство в новом репозитории
- **THEN** он получает публичный репозиторий с работающим PR-процессом без необходимости отключать защиту для обычных изменений
