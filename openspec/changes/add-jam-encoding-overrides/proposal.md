# Proposal

## Why

На узле amster2 HPT хранит перекодированный KOI8-R текст вместе с исходным CHRS CP866. Резервная кодировка не помогает: явный CHRS имеет приоритет, поэтому FFIDO показывает искажённый текст.

## What Changes

- Добавить `ftn.jam_encoding_overrides`: отображение относительного пути JAM без расширения в принудительную кодировку.
- Применять настройку к чтению всех текстовых полей и новым записям, сохраняя обычные правила для остальных баз.
- Отклонять неверные настройки и неоднозначные правила для физических алиасов при запуске.
- Добавить опциональную локальную политику внешнего HPT: CP866/CHRS для обычных эх и обход таблиц для utf-8, с отказом при ошибке настройки.
- Проверить конфигурацию, чтение, публикацию и отсутствие изменений исторической JAM; применить локальную сборку на amster2 без публикации.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `jam-storage`: явное исключение к приоритету CHRS для настроенной локальной JAM.

## Impact

Сервер `apps/backend/`: конфигурация, каталог/доступ JAM, main и административный инструмент, тесты и документация. gRPC-контракт сохраняется. Рецепт, patch и изолированный сценарий внешнего HPT находятся в deploy/hpt/. На VPS требуется локальная непубликованная сборка; официальная v1.0.1 ещё не понимает настройку. Рабочие базы не перекодируются.
