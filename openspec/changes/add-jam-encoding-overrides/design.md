# Design

## Context

См. proposal.md. Все RPC и переходы почты открывают базы через JamAccess; каталог создаётся в main и point_mail_admin. PrepareAppend принимает Unicode и может сохранять исходный CHRS перенесённого сообщения.

## Goals / Non-Goals

**Goals:** единая политика чтения/записи для физической JAM, включая mailbox; fail-fast конфигурация.
**Non-Goals:** исправление исторических CHRS, смена gRPC, автоматическое определение кодировки.

## Decisions

- Ключ — безопасный относительный путь без расширения, а не имя эхи: так можно адресовать netmail/mailbox и не зависеть от API ID. Регистр пути значим. Неиспользованные ключи запрещены.
- Парсер проверяет тип/лимиты и iconv в обе стороны. Каталог назначает override физическим JamFiles, запрещая разный override у алиасов (включая отсутствие override у одного алиаса).
- Завершённые входящие переходы повторно используют журнал по raw source identity: смена декодирования не пересчитывает их payload hash и не создаёт новые копии.
- JamAccess передаёт выбранную кодировку и признак force в JamMessageBase. Чтение игнорирует CHRS при force; новая запись заменяет только строки CHRS в копии входных подполей. Остальные kludge сохраняются. Это охватывает RPC/UUE/admin без разрозненных правил.
- Для amster2 локально собрать Linux amd64 сервер и admin, установить непубликованное дополнение к официальному образу. Не менять BUILD.json или подписанные манифесты и не выдавать локальные бинарники за официальный релиз. До официального выпуска этой функции автоматическое применение новых версий приостановить: иначе штатный v1.0.1 потеряет настройку. Проверка доступных версий сохраняется; дальнейшее включение применения описать оператору.

## Risks / Trade-offs

- Неверный принудительный профиль искажает отображение → явные правила, тесты разных кодировок, сохранение прежнего поведения без правил.
- Перенос почты между разными кодировками → нормализация CHRS только у нового append, тест с исходным CHRS.
- Локальная сборка не содержит production-подписи → держать отдельно, фиксировать хэши и исходный diff, не публиковать; после выпуска переключиться на официальный образ.

## Migration Plan

Сделать согласованный backup; остановить писателей; снять SHA-256 JAM до/после настройки и чтения; установить локальные бинарники в сервер и worker, добавить точные override KOI8-R и UTF-8. Проверить TLS RPC с живыми данными без постинга, сессии, чистый экспорт. При сбое вернуть прежнюю конфигурацию/запуск, не откатывать базы из старого backup. Все VPS-файлы внутри /home/yurik/fido.


## Согласованное дополнение HPT

После разрешённой проверки исходящего транспорта добавлена опциональная политика
`FFIDO_HPT_KOI8_CP866=1` в отдельном worker. Patch к pinned HPT меняет CHRS только
в экспортируемой копии обычных эх после outtab, а для utf-8 обходит outtab/intab.
При отключённом RecodeMsgBase, отсутствии таблиц или ошибке загрузчика запуск
отклоняется. Рецепт и проверка воспроизводимы из deploy/hpt/; исходные зависимости
и их версии не обновляются. Проверки используют отдельные JAM/PKT без сети и
рабочих очередей. Неверно перекодированная история остаётся без изменений.
