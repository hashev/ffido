# Design

## Context

Мотивация описана в proposal.md. `MessageScreen.navigate` выбирает индекс ±1, подгружает страницы и заменяет строку результатом `getMessage`, уже отмеченным прочитанным. `reader_app.dart` и `personal_conferences.dart` передают только одну конференцию. Главный каталог сортируется через `Conference.compareForCatalog`, после возврата перечитывается; персональные списки имеют собственный порядок.

Существующий `ListMessagesRequest` не содержит фильтра unread, но возвращаемые строки содержат `is_read`. `getConferenceMessages` поддерживает offset, сортировку и проверенный anchor. Загрузка тела отмечает чтение, поэтому использовать её для поиска кандидатов нельзя. Существующие отмена, epoch и version защищают экран от поздних ответов.

В Android/iOS/macOS/Windows/Web уже есть платформенные ресурсы иконок, но генератор launcher-иконок в pubspec отсутствует. Linux GTK runner сейчас не назначает иконку окна.

## Goals / Non-Goals

**Goals:** сохранить порядок источника, не отмечать пропускаемые сообщения прочитанными, использовать текущий API и повторно применять защиту сессии ко всему межэховому переходу. Хранить выбранный мастер иконки вместе с проектом.

**Non-Goals:** серверный фильтр unread, новый протокол, изменения Netmail и цепочек, скрытие прочитанных строк из обычного списка, переход назад между эхами, новые зависимости и обновление toolchain, публикация сборок.

## Decisions

### Контекст обхода передаётся из источника

При открытии экрана передать неизменяемый снимок ID и метаданных текущего полного списка, текущий индекс и идентичность сессии. Источники — главный каталог с текущим поиском, закладки и история. Выбирать только читаемые EchoArea, сохраняя их относительный порядок. Не пересортировывать снимок после каждого прочтения: иначе эха перемещается в группу прочитанных и нарушает последовательность. При возврате обновлять исходный список штатным способом. Повторный запрос всего каталога вместо снимка отвергнут: он теряет фильтр и порядок персонального экрана.

### Поиск по кратким строкам, без изменения API

Для обычной эхи искать ближайшую строку `isRead == false` в направлении кнопки, исключая текущее сообщение и уже успешно открытые в данном проходе ID. При необходимости последовательно догружать страницы, включая страницы целиком из прочитанных; смещение считать по всем полученным строкам, а не по числу непрочитанных. Для проверки кандидата использовать свежие краткие данные, не приватный или устаревший fallback. Защиту поколения базы и остановку на пустой/повторной странице сохранить.

«Предыдущее» ищет непрочитанное перед текущей позицией только в той же эхе. Возврат к уже прочитанному доступен ручным выбором в списке. «Следующее» ищет вперёд; при исчерпании этого направления переходит к следующей эхе. Автоматического оборачивания к сообщениям перед текущей позицией нет. В цепочках и прочих областях используется прежняя логика.

Серверный фильтр рассмотрен, но не выбран: он требует изменения общего контракта и стабильной пагинации набора, который сокращается при чтении. Клиентский обход сохраняет существующий порядок и совместимость.

### Межэховый переход как одна отменяемая операция

Проверять следующие EchoArea по снимку, запрашивая актуальные права и краткие сообщения. Известный старый ноль не служит доказательством отсутствия новых писем; неизвестная статистика тоже требует проверки. Эхи без кандидатов пропускать. Для найденной эхи открывать первое непрочитанное в текущей сортировке её писем, затем атомарно заменять контекст экрана, заголовок, права, список и выбранное письмо. Не накапливать маршруты по одному на каждую эху. При пустой исходной эхе дать явное действие продолжения в следующую эху без выбора прочитанного письма.

Во время всей операции блокировать повтор, проверять epoch/version и отмену. Сетевой сбой оставляет текущее письмо и повтор того же перехода; отказ в доступе или удаление следующего кандидата исключает его из обхода. Отзыв доступа к текущей области сохраняет штатное очищение. Конец списка показывает отсутствие дальнейших непрочитанных, без перехода в начало. При отсутствии переданного контекста доступен только обход текущей эхи.

### Иконка из одного выбранного мастера

Наличие файла проверено при подготовке предложения. До apply ресурс не копируется и иконки не меняются.

Подготовить производные по существующим Contents.json, Android mipmap, Windows ICO и web manifest/favicon. Использовать качественное уменьшение и при необходимости расширение тёмно-синего поля, без перерисовки выбранного изображения и искажения пропорций. Maskable-вариант получает дополнительные поля. Малые размеры проверить визуально. Документировать воспроизводимое преобразование в существующем `apps/frontend/tool/`, не добавляя runtime-зависимостей.

Linux получает PNG в bundle и назначение иконки существующим GTK API; путь вычисляется относительно executable/bundle, не cwd. Отдельная система установки desktop-файлов и пакетирования не вводится. Добавление только PNG без подключения к runner отвергнуто: окно продолжило бы использовать прежнюю иконку.

## Risks / Trade-offs

- [Много прочитанных страниц] → последовательная загрузка кратких строк, индикатор занятости и отмена; никаких загрузок тел ради поиска.
- [Чтение другим устройством или новые письма между запросами] → свежие данные перед выбором и учёт локально открытых ID; абсолютная атомарность проверки unread и открытия без нового API не гарантируется. Новые поступления в уже пройденную часть доступны после обновления/повторного входа.
- [Удаления и смена поколения] → действующие ошибки устаревшего списка и явное обновление; не смешивать страницы разных поколений.
- [Системные маски обрезают собаку/дискету] → безопасные отступы и визуальная проверка уменьшенных и maskable-вариантов.
- [На macOS нельзя собрать все платформы] → локальные доступные проверки и сборки, остальные платформы проверяются существующей CI; непроверенное перечисляется в отчёте.

## Migration Plan

Изменение поставляется обычным обновлением клиента без миграции данных и сервера. При apply сначала сохранить мастер, затем добавить навигацию и ресурсы, выполнить проверки. Откат возвращает прежнюю навигацию и ресурсы, сохраняя серверную прочитанность уже открытых писем. Коммит и публикация требуют отдельного запроса пользователя.
