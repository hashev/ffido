# Proposal

## Why

JAM-архив FFIDO содержит готовую базу знаний: решения технических проблем, историю обсуждений, ответы участников и FTN-метаданные. MCP позволит ассистенту находить подтверждённые первоисточниками ответы, восстанавливать контекст и готовить дайджесты, используя существующие права доступа FFIDO.

## What Changes

- Добавить `ffido-mcp`: локальный stdio MCP-сервер на C++23, подключающийся к действующему backend по TLS gRPC без прямого доступа к JAM/HPT/SQLite.
- Предоставить инструменты каталога областей, выборки за период, поиска по выбранным областям, чтения письма и цепочки, получения технических данных.
- Добавить совместимые archive RPC для поиска и чтения без изменения прочитанности, истории и позиции; переиспользовать JAM, кодировки и контроль доступа backend.
- Возвращать точные ссылки на сообщения, UTC-даты, авторов, признаки неполноты и продолжение выборки. Поддержать пользовательские MCP-шаблоны исследования темы, дайджеста и разбора цепочки; генерацию текста выполняет ассистент.
- Включить подготовку и отправку текстовых сообщений и ответов после просмотра точного содержимого, с идемпотентностью и повторной проверкой прав. Успех означает локальное сохранение, не доставку в FidoNet.
- Области ограничить одновременно правами профиля и явными локальными списками разрешений MCP для чтения и публикации; приватная почта не подключается автоматически.
- Отложить прочитанность, закладки, кросспостинг, загрузку/скачивание UUE, автоматический мониторинг, векторный поиск и встроенную LLM.

## Capabilities

### New Capabilities

- `archive-research`: ограниченные чтение, поиск и получение контекста JAM-архива без персональных побочных эффектов, с проверяемыми источниками.
- `mcp-server`: stdio MCP-адаптер FFIDO, его протокол, инструменты, изоляция профиля, шаблоны исследования и конфигурация.
- `mcp-publication`: предварительный просмотр, подтверждаемая отправка и безопасный повтор текстовой публикации через MCP.

### Modified Capabilities

Нет. Семантика существующих RPC и клиентских сценариев сохраняется; новые archive RPC описаны отдельной capability. В частности, обычный `GetMessage` продолжает отмечать письмо прочитанным, а `FindMessage` — отмечать найденный результат.

## Impact

- `apps/backend/`: новые archive-методы сервиса, просмотр и проверка публикации, gRPC handlers и отдельный клиентский executable `ffido-mcp`; существующие `PeekMessage`, `GetThread`, `GetMessageTechnicalData`, `CreateMessage`, `EchoAccess`, `JamAccess` и алгоритмы поиска служат основой.
- `contracts/ffido/v1/ffido.proto`: только добавления; регенерация C++ и Dart, обновление контрактных тестов. `apps/frontend/` не получает новых экранов, существующее поведение сохраняется.
- Корневой CMake, серверная упаковка, `scripts/`, backend README и документация подключения MCP: сборка, тесты и поставка нового executable для Linux/macOS.
- Без миграции JAM/SQLite и новых runtime-зависимостей: использовать существующие gRPC, protobuf и nlohmann/json. MCP transport ограничен stdio; публичный HTTP endpoint и его авторизация требуют отдельного изменения.
