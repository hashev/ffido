# Proposal

## Why

FFIDO готов к публичному распространению исходников и установочных пакетов, но текущий каталог содержит незавершённый перенос в монорепозиторий и настройки локальной разработки. Нужен воспроизводимый выпуск с управляемым доступом к изменениям и понятной установкой без доступа к рабочей FTN-ноде.

## What Changes

- Подготовить проверяемый чистый каталог публикации с исходниками, примерами конфигурации, лицензией и уведомлениями зависимостей; сохранить исходное рабочее дерево и не публиковать локальные данные.
- Описать создание публичного GitHub-репозитория, приглашение участников, режим PR `Collaborators only` и защиту `master`: изменения через PR и успешный CI, ноль обязательных approvals, без bypass.
- Добавить CI проверок PR и автоматический публичный prerelease после каждого слияния; стабильные релизы выпускать по тегам `vX.Y.Z` на проверенном коммите `master`.
- Выпускать Flutter-клиент для macOS, Windows, Android и Linux; сервер с admin/helper/wrapper для Linux и macOS. Публиковать контрольные суммы, версии и необходимые runtime-зависимости.
- Подготовить устойчивую Android-подпись и явный режим подписей desktop-пакетов. Не выдавать debug APK за готовый публичный пакет.
- Переработать корневой README как руководство пользователя и администратора; добавить подробную инструкцию первой публикации и сопровождения репозитория.

## Capabilities

### New Capabilities

- `repository-governance`: публичное чтение и скачивание, управляемое участие и обязательные PR в master.
- `release-distribution`: проверенные пакеты, автоматические prerelease и стабильные версии, подписи и целостность.
- `publication-readiness`: чистый публикуемый каталог, лицензирование и полное руководство установки/первой публикации.

### Modified Capabilities

Нет. Сетевой контракт и функциональные требования клиента и сервера не меняются.

## Impact

Затрагиваются `.github/`, корневые `.gitignore`, README и юридические файлы, `scripts/`, документация, packaging/backend CMake install и настройки Flutter-платформ в `apps/frontend/`. Используются существующие `apps/backend/`, `contracts/`, `tools/proto/` и общий `openspec/`; зависимости и toolchain не обновляются попутно. iOS/Web сохраняются в исходниках, но не входят в матрицу выпуска. Публикация в магазины и перенос backend на Windows не входят в изменение. Создание удалённого репозитория, commit/push и изменение рабочей ноды amster2 не выполняются автоматически.

Владелец GitHub, окончательное имя, лицензия, вариант истории, идентификаторы приложения и подписи остаются решениями владельца до первой публикации; до их выбора применяются проверяемые placeholders и явные блокировки выпуска.
