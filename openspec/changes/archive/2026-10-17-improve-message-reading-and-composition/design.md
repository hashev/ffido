# Design

## Context

См. proposal.md. Наблюдаемое состояние:

- `apps/frontend/lib/pages/message_screen.dart`: список и полное письмо находятся в одном состоянии; `load(more: true)` сбрасывает `selected`, навигационной панели нет. Обе кнопки ответа вызывают `compose(reply: true)`.
- `_ComposeScreen`: обычный ответ не заполняет `body`, пересылка формирует текст, но `conferenceId` фиксирован. Отправка идёт через `sendMessage`, а не через вспомогательные `replyToAll`/`forwardMessage` репозитория.
- Тело отображается обычным `SelectableText`, редактируется обычным `TextField`. Тесты проверяют сохранность отступов и переносов: это остаётся контрактом.
- `ConferenceRepository` уже предоставляет пагинацию, поиск и `canPost`; сервер перечисляет эхи с правом чтения ИЛИ публикации и проверяет ACL при отправке.
- `main.dart` задаёт тёмную тему и часть стилей вручную. Текущий вид не доказывает корректность состояний hover/focus и контраста всех элементов.

## Goals / Non-Goals

**Goals:** общий plain-text документ для отображения и отправки, независимые состояния списка и чтения, пересылка с явно выбранным назначением, согласованная доступность действий.

**Non-Goals:** netmail, личный ответ, массовая рассылка по эхам, HTML/Markdown-редактор, копирование всего интерфейса GoldED, настройки пользовательских цветовых схем, изменение сервера или формата JAM. Новую настройку переключения темы не добавляем; обе палитры проверяем компонентными тестами.

## Decisions

### 1. Контекст навигации хранится отдельно от выбранного письма

Сохранять упорядоченный список ID, режим конференции/цепочки, курсор загруженных страниц, выбранный ID и позицию прокрутки списка. «Предыдущее» означает позицию выше в текущем списке, «Следующее» — ниже; при сортировке newest это соответственно более новое и более старое письмо. Не вычислять соседей арифметикой JAM-номеров.

Разделить дозагрузку списка и открытие detail, чтобы переход страницы не сбрасывал читаемое письмо. Панель внизу Scaffold остаётся видимой при прокрутке. При переходе прокрутка тела начинается сверху, возврат к списку сохраняет его позицию. Следующая страница подгружается по нажатию на границе, без загрузки всех писем заранее. Запросы защищены существующими epoch/version/cancellation; до успешного detail прежнее письмо сохраняется, кроме отказа доступа или смены сессии.

Offset API не гарантирует снимок при внешнем toss/pack. Убирать дубли по ID, не зацикливать дозагрузку при пустой странице; при NOT_FOUND или смене поколения предлагать обновить список, не подменять письмо с тем же числовым номером. Новый snapshot/cursor API в эту работу не входит.

### 2. Одно действие публичного ответа

Согласовано: «Ответить в эху», назначение — исходная эха, адресат — автор оригинала. Поля получателя ответа остаются информационными, как в текущем UI; существующее требование явного переопределения в `message-replies` не меняется этой работой. Удалить дублирующее действие из UI; репозиторный alias `replyToAll` не превращать в другую сетевую операцию, проверить существующие вызовы и тесты.

### 3. Цитата является частью редактируемого документа

При открытии ответа вставить тело оригинала один раз, добавив `> ` в начало каждой строки, в том числе уже цитируемой; пустую строку для собственного ответа оставить вне цитаты, поставить туда курсор. Автоматическое добавление цитат в момент отправки исключить. Пользователь может удалить любую часть, сохранить отступы, отвечать между строками. Полное тело оригинала остаётся видимым и редактируемым, без скрытого исключения подписи.

Моноширинный `TextField` с контроллером, переопределяющим `buildTextSpan`, даёт подсветку внутри редактируемого текста, без отдельного несинхронного preview и внешнего rich-text пакета. Разбор строк и палитра общие с `SelectableText.rich` чтения. Обязательно сохранять composing range IME, selection и undo; перенос по ширине только визуальный. Цвета не добавляют управляющие последовательности в отправляемую строку. Подсветка не является байтовым предпросмотром JAM: сервер по-прежнему добавляет служебный хвост и нормализует Н → H перед CP866.

### 4. Правила распознавания и цвета по принципу GoldED

Распознавать только префикс строки после начальных пробелов: группы `>` и короткие инициалы из букв/цифр перед `>` (до 8 символов), допускающие вложенные префиксы и пробелы между ними. Глубина — количество маркеров `>` в префиксе. Примеры: `>`, `>>`, ` AB>`, `AB>>`, `> AB>`, `AB> CD>`; `a > b` не является префиксом цитаты. Обычный текст, цитаты нечётной глубины и цитаты чётной глубины получают три различимых цвета. Начальная палитра: янтарный и голубой для цитат на тёмном фоне, более тёмные соответствующие оттенки на светлом; точные оттенки подбираются по контрасту тестами. Маркеры сохраняются, поэтому структура читается и без цвета.

Проверенные примеры в интернете:

- [Официальная конфигурация цветов GoldED+](https://raw.githubusercontent.com/golded-plus/golded-plus/master/cfgs/config/gedcolor.cfg): раздел Message Text, строки 77–82; нечётные уровни задаёт `READER QUOTE1`, чётные — `READER QUOTE2`, отдельно задан обычный текст. Это основание для принципа чередования, а не требование копировать фиксированные терминальные цвета.
- [Справка GoldED+](https://github.com/golded-plus/golded-plus/blob/master/cfgs/config/goldhelp.cfg): пример организации навигации и операций ответа в текстовом редакторе.
- [Галерея проекта FidoIP](https://sourceforge.net/projects/fidoip/) и [пример скриншота](https://a.fsdn.com/con/app/proj/fidoip/screenshots/241430.jpg/max/max/1): визуальный ориентир терминального интерфейса с GoldED. Наличие таких скриншотов не подтверждает само по себе поведение редактора FFIDO; проверяем подсветку своими тестами.

### 5. Пересылка — новое письмо в выбранную эху

Действие доступно при чтении исходного письма даже без `canPost` исходной эхи. Открыть выбор назначения с поиском и пагинацией через `ConferenceRepository`, оставить только `canPost`, включая post-only. Перед отправкой повторно получить назначение для актуализации прав; серверная ACL остаётся окончательной. Если разрешённых эх нет — понятное пустое состояние.

В редакторе явно показывать исходную и целевую эхи, имя/адрес автора, тему и дату; тело пересылки и комментарий редактируются в том же поле. Шаблон инициализируется один раз, смена назначения не возвращает удалённые цитаты. Получатель по умолчанию All, тема Fwd без повторного префикса, `inReplyTo` отсутствует. Отправлять окончательное тело напрямую, чтобы репозиторий не добавил второй блок пересылки. После успеха обновить данные назначения; исходное письмо оставить открытым.

Операционный ключ соответствует всему неизменному запросу, включая назначение. При неопределённом результате заморозить все поля и выбор назначения, повторить тот же запрос и ключ; после определённого отказа разрешить правки и сформировать новый ключ. При запрете назначения сохранить документ, убрать недоступный выбор и предложить другой; при смене сессии закрыть старый редактор и очистить список.

### 6. Общие стили и адресный аудит действий

Настроить Material-состояния темы для кнопок, IconButton и кликабельных строк; исправлять локальные стили только там, где они обходят тему. Охват: подключение, reader_app, карточки, чтение/редактор, настройки, профиль, закладки, история. Активный элемент имеет hover/focus и click cursor; disabled не имеет click cursor; текст сохраняет text cursor. Для иконок — tooltip и semantics, для важных действий — видимая подпись. Клавиатурный фокус и касание работают без hover. Не оборачивать весь экран в MouseRegion, иначе курсор потеряет смысл.

## Risks / Trade-offs

- Подсветка может нарушить IME или позицию выделения → единый plain-text controller, тест composing/selection/undo и ручная проверка русской раскладки macOS/Android.
- Большое письмо может тормозить при каждом вводе → линейный разбор строк без сложных регулярных выражений; проверить длинную цитату и мягкий перенос.
- Новые письма меняют offset списка → дедупликация и явное обновление при устаревших ID; не обещать стабильный снимок средствами существующего API.
- Права назначения могут измениться после выбора → предварительная актуализация плюс серверный отказ, сохранение черновика и отсутствие ложного успеха.
- Визуальное совпадение с GoldED не гарантирует доступности → проверить собственный контраст и фокус, сохранить текстовые маркеры глубины.

## Migration Plan

Изменить и проверить только клиент, собрать macOS и Android существующим toolchain. Сервер, API, реальные HPT/JAM и пользовательские профили не мигрировать. Проверки отправки проводить через fake transport и временную тестовую инфраструктуру; ручной осмотр с реальным сервером не требует публикации тестовых писем в рабочие эхи. Откат — предыдущая сборка клиента.
