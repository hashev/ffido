# Spec Delta

## ADDED Requirements

### Requirement: Отмена при медленном потребителе результатов
Если потребитель временно не читает stdout, MCP SHALL продолжать принимать уведомления отмены уже активных вызовов и передавать отмену их RPC. Ожидание вывода SHALL не удерживать блокировку учёта активных вызовов. Память ожидающих ответов SHALL иметь конечный бюджет; при его исчерпании процесс SHALL управляемо завершать соединение без потери подтверждённых публикаций и без ложного успеха.

#### Scenario: Заполненный выходной канал
- **WHEN** потребитель перестал читать stdout и отправил отмену другого активного инструмента
- **THEN** отмена достигает его RPC до освобождения stdout, а расход памяти остаётся в заданном бюджете

#### Scenario: Возобновление чтения
- **WHEN** потребитель возобновил чтение до исчерпания бюджета ожидающих ответов
- **THEN** сервер передаёт целые JSON-RPC сообщения с правильными ID и продолжает обслуживать ping и инструменты

#### Scenario: Переполнение бюджета ответов
- **WHEN** потребитель продолжает посылать запросы без чтения ответов и бюджет ожидающего вывода исчерпан
- **THEN** сервер завершает соединение с локальной диагностикой без секретов, отменяет незавершённые RPC и не сообщает об успешной публикации без подтверждения backend

#### Scenario: EOF или закрытый stdout
- **WHEN** вход закрыт при заполненном выводе либо потребитель закрыл stdout
- **THEN** MCP управляемо завершает соединение, отменяет незавершённые RPC и освобождает ожидающие результаты без бесконечного ожидания вывода
- **AND** подтверждённая backend-публикация остаётся доступна по прежнему operation ID при повторе

### Requirement: Допуск подготовленных ответов MCP
Ограничение четырёх незавершённых tools/call SHALL учитывать вызовы с готовым результатом до его постановки в ограниченную очередь вывода. Очередь SHALL отдельно ограничивать накопление подготовленных ответов. Превышение допуска SHALL давать явную ресурсную ошибку до обращения нового инструмента к backend.

#### Scenario: Готовые результаты ожидают вывода
- **WHEN** четыре допущенных инструмента ещё не передали свои ответы в ограниченный выходной буфер и приходит пятый tools/call
- **THEN** пятый инструмент получает ресурсную ошибку без запуска его backend-операции
- **AND** после освобождения допуска последующий инструмент может выполняться

### Requirement: Отмена ожидания черновика MCP
Ожидание завершения другой операции над черновиком SHALL допускать отмену и учитывать исходный общий deadline. Отмена ожидающего инструмента SHALL освобождать его допуск до окончания удерживающей операции и не менять подтверждённое состояние публикации.

#### Scenario: Отмена ожидающего инструмента
- **WHEN** один инструмент удерживает операцию черновика, а другой ожидает тот же черновик и отменяется
- **THEN** ожидающий инструмент прекращает ожидание до завершения первого, а независимый инструмент чтения остаётся доступен
- **AND** повтор подтверждённой отправки сохраняет прежний operation ID без дублирования публикации
