# Spec Delta

## ADDED Requirements

### Requirement: Запись публикаций API в CP866
При серверной настройке CP866 новые публикации API SHALL сохранять тело, тему, имя автора и имя получателя в JAM как байты CP866 и указывать CHRS: CP866 2. Unicode транспортного запроса SHALL преобразовываться на сервере до записи. Настройка SHALL действовать для новых сообщений и ответов независимо от CHRS родителя.

#### Scenario: Кириллица из клиента
- **WHEN** клиент отправляет текст, тему и имена с русскими буквами, включая Ё/ё, при настройке CP866
- **THEN** сырые байты тела в .jdt и соответствующих подполей в .jhr совпадают с независимым эталоном CP866, а повторное чтение возвращает исходные строки

#### Scenario: Ответ на сообщение UTF-8
- **WHEN** клиент отвечает на существующее письмо с CHRS UTF-8 при серверной настройке CP866
- **THEN** новое письмо записывается в CP866 с собственным CHRS: CP866 2, сохраняя reply-связь и не меняя родителя

### Requirement: Отказ без потерь при непредставимом тексте
Если тело или текстовое подполе публикации нельзя представить в настроенной CP866, сервер SHALL отклонять её контролируемой ошибкой валидации до записи JAM и подтверждения отправки. Замена символов, транслитерация и молчаливое переключение в UTF-8 SHALL не выполняться. Клиент SHALL сохранять текст для исправления.

#### Scenario: Эмодзи или неподдерживаемая буква
- **WHEN** тело, тема или имя содержит символ вне CP866
- **THEN** API возвращает ошибку валидации, файлы .jhr/.jdt/.jdx не меняются и сообщение не считается сохранённым
