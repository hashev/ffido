# Design

## Context

Мотивация и границы изменения описаны в proposal.md. Ревью выполнено по текущему рабочему дереву, включая существующие пользовательские изменения. Основные спецификации отсутствуют. Приложение использует StatefulWidget, глобальные репозитории, http и SharedPreferences; менять эту архитектуру для исправлений не требуется.

### Найденные дефекты

### Исходная проверка

- `flutter test --no-pub`: 25 тестов прошли.
- `flutter analyze --no-pub`: exit 1, шесть info: два dangling_library_doc_comments, три use_super_parameters, один avoid_print в settings.dart. Ошибок и предупреждений analyzer нет.
- Реальный API, release-сборки и устройства не проверены. URL example.com является заглушкой, а TODO-функции не считаются реализованными сценариями.

## Goals / Non-Goals

**Goals:** воспроизводимые исправления с детерминированными тестами; единая обработка ответов для всех HTTP-методов; отсутствие гонок без новых библиотек состояния.

**Non-Goals:** переписывание глобальных singleton, новый транспорт, миграция UI-моделей, изменение контрактов сервера и завершение TODO-функций. Не расширять ревью случайными рефакторингами.

## Decisions

1. **Сначала статус, затем безопасная обработка тела.** Для 2xx разрешить пустое тело, иначе требовать объект JSON, декодируя response.bodyBytes как UTF-8. Для HTTP-ошибок извлекать сообщение и errors по возможности; сбой декодирования не должен заменять HTTP-статус сетевой ошибкой. Сохранить существующие публичные типы исключений; подклассам добавить совместимые параметры статуса, а серверные ошибки классифицировать диапазоном 500–599. Преобразовывать списки ошибок полей явно; при неправильной форме сохранять 422 и доступную диагностику. Альтернатива замены клиента на Dio не нужна.

2. **Последний пользовательский запрос имеет приоритет.** Использовать монотонный номер запроса и mounted перед каждым завершением await, включая catch. Инвалидировать старую операцию уже при изменении ввода, не только при отправке следующего запроса; отменять debounce при очистке/обновлении. Обновление и retry берут текущий текст. Достаточна минимальная общая процедура загрузки внутри экрана; физическая отмена HTTP не требуется. Для профиля добавить защиту после await. Для тестов допустима минимальная подстановка репозитория через необязательный параметр экрана, без смены глобальной архитектуры.

3. **Кеш соответствует запросу и не подменяет ошибки доступа.** Сохранять limit в метаданных первой страницы; legacy-кеш без достаточных метаданных игнорировать и перезагружать. Проверять свежесть, timestamp и корректность JSON. Fallback только на NetworkException и ServerException при offset 0, включая forceRefresh. Не добавлять устаревший offline-кеш и не менять пяти минутный TTL. Не возвращать кеш для 401/404/422. Вместо второго хранилища оставить SharedPreferences.

4. **Одна семантика обычного ответа.** Значения по умолчанию в toJsonForReply использовать fromName/fromAddress; сохранить явные переопределения и in_reply_to. Обновить существующий тест и добавить случай явного адресата. replyToAll остаётся отдельной незавершённой функцией.

5. **Штатная release-конфигурация.** Добавить минимальные сетевые разрешения в Android main manifest и обе macOS entitlement-конфигурации. Вместо произвольного динамического IconData использовать компактное отображение поддерживаемых кодов в константные Icons с fallback Icons.forum. Сохранять поля API-модели; неподдерживаемое семейство также даёт fallback. Не отключать tree shaking для обхода проблемы.

6. **Проверки защищают поведение.** Использовать http/testing.dart MockClient, SharedPreferences.setMockInitialValues и контролируемые Completer для обратного порядка ответов и dispose. При необходимости добавить обычный конструктор для изолированной инъекции уже существующих зависимостей репозитория, сохранив getInstance. Не подавлять lint; устранить шесть исходных замечаний точечными правками без переформатирования остальных файлов.

## Risks / Trade-offs

- Нет реального сервера → тестировать документированные тела и транспорт с MockClient; интеграцию не объявлять проверенной.
- Пользовательские изменения многочисленны → сохранить снимок списка изменённых путей и проверить итоговый diff; не откатывать существующую работу.
- Старый кеш теряет совместимость метаданных → безопасная повторная загрузка; основной API и данные сервера не мигрируют.
- Набор константных иконок ограничен → для неизвестных значений использовать стабильную стандартную иконку.
- Платформенные инструменты могут быть недоступны → выполнить доступную release-сборку, явно указать непройденные платформенные проверки.

## Migration Plan

Применять исправления небольшими группами с регрессионными тестами; затем выполнить общий анализ, тесты и доступную release-сборку. Старый кеш инвалидируется автоматически; пользовательские серверные данные не меняются. Откат возможен обратным применением только diff этого изменения, без сброса рабочего дерева.
