# Proposal

## Why

Ревью текущего Flutter-клиента выявило ошибки обработки HTTP, асинхронного состояния, кеширования и сетевой конфигурации, способные ломать существующие сценарии. Требуется исправить подтверждённые дефекты и закрепить поведение регрессионными тестами, сохранив пользовательские изменения.

## What Changes

- Корректно обрабатывать пустые успешные HTTP-ответы, ошибки без JSON, UTF-8, ошибки валидации и все статусы 5xx; сохранять HTTP-статус в исключениях.
- Исключить обновления закрытых экранов и применение устаревших результатов поиска; отменять debounce при очистке, сохранять запрос при обновлении.
- Изолировать кеш первой страницы по параметрам запроса и разрешить сетевой fallback только для подходящих ошибок, без маскирования ошибок авторизации.
- Направлять JSON обычного ответа автору исходного сообщения.
- Исправить сетевые разрешения Android/macOS и устранить препятствие release-сборке, связанное с динамическими MaterialIcons.
- Добавить тесты дефектов, провести анализ и доступные проверки сборки, актуализировать затронутые комментарии и документацию.
- Не реализовывать сервер, авторизацию, пагинацию UI, экран реальных сообщений, отправку, историю, закладки и другие TODO в рамках ревью. Не менять архитектуру и зависимости без необходимости.

## Capabilities

### New Capabilities

- `api-transport`: обработка HTTP-ответов и типизированных ошибок.
- `conference-browsing`: согласованное асинхронное состояние списка и поиска, корректный кеш конференций.
- `message-replies`: адресация обычного ответа исходному отправителю.
- `platform-runtime`: исходящая сеть и безопасное отображение иконок в release-клиенте.

### Modified Capabilities

Нет: существующие основные спецификации отсутствуют.

## Impact

Затронуты `lib/api/`, `lib/repositories/conference_repository.dart`, `lib/models/message.dart`, `lib/pages/reader_app.dart`, `lib/pages/profile_screen.dart`, платформенные разрешения Android/macOS и тесты. REST endpoints и обязательные поля моделей сохраняются. Реальный API не настроен: URL использует example.com, поэтому проверка транспорта будет выполняться с подставным HTTP-клиентом. Все существующие незакоммиченные изменения являются исходной базой и должны сохраниться.
