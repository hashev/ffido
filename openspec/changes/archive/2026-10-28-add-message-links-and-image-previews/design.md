# Design

## Context

Мотивация — в proposal.md. Наблюдаемые точки интеграции:

- `MessageScreen` выводит тело выбранного письма через `UueBody` с ключом из ID, hash тела и epoch репозитория. `UueBody.text()` использует `SelectableText.rich(ftnTextSpan(...))`; текст до/после UUE-карточек выводится отдельными фрагментами.
- `lib/utils/ftn_text.dart` сохраняет текст и оформляет FTN-цитаты; тот же renderer использует `FtnTextController` редактора. В него нельзя безусловно добавить обработчики открытия URL.
- `UueAttachmentCard.preview()` проверяет фактический PNG/JPEG/GIF/WebP через `uueImageInfo`, размеры и ограниченно декодирует первый кадр. Текущие UUE-картинки не имеют fullscreen/share; их функциональность не расширяется этим изменением.
- `UueFiles.save` уже предоставляет безопасное имя и сохранение через Android channel, desktop file_selector и Web download. Системного открытия URL и отправки файла сейчас нет.
- Android имеет INTERNET, macOS release — sandbox/network.client и user-selected.read-write. Аудит релиза сравнивает точный список Android-компонентов. Транспорт и консольные Dart acceptance tools должны оставаться независимыми от Flutter UI/plugins.

## Goals / Non-Goals

**Goals:** отделить разбор текста, ограниченную загрузку, представление и платформенные действия; дать тестируемые границы и единое владение байтами preview/fullscreen/share.

**Non-Goals:** HTML/WebView, Open Graph, серверное скачивание URL, галерея всех картинок конференции, анимация GIF/WebP, редактирование изображений, расширение UUE-viewer и миграция протокола/данных.

## Decisions

### 1. Отдельное интерактивное представление прочитанного текста

Добавить чистый Dart-разбор диапазонов URL и отдельный stateful reader-виджет с управляемыми recognizers/focus/actions. В `UueBody` использовать его только для читаемых текстовых фрагментов; `FtnTextController` остаётся без интерактивных действий. Сохранить моноширинный стиль, границы строк, цвета цитат вне URL и точный `toPlainText()`. Ссылки получают контрастный цвет и подчёркивание, доступное действие открытия и видимый keyboard focus. Распознавать `http://`, `https://`, `www.` без пробелов и C0/DEL; сбалансировать скобки, отделять внешнюю пунктуацию, сохранять query/fragment/Unicode и исходный текст. `www.` перед запуском получает HTTPS; userinfo и остальные схемы не запускаются.

Для полного и raw-представления UUE использовать существующее распознавание кодированных диапазонов, не linkify строки данных даже при похожей последовательности байтов. Preview-карточки разместить после соответствующего текстового фрагмента в порядке первых URL, не заменяя символы тела WidgetSpan-ами. Повторы URL объединить в пределах всего письма, включая разные текстовые фрагменты. Альтернатива с заменой всех SelectableText на HTML отвергнута: она меняет FTN-отступы, копирование и поверхность исполнения.

### 2. Открытие внешнего браузера и платформенные действия

Выбрать `url_launcher` 6.3.3 и `share_plus` 13.3.1, закрепив версии и lockfile. Их опубликованные требования совместимы с текущими Flutter 3.47.7 / Dart 3.13.5, AGP 9.1.0, Kotlin 2.4.0 и Gradle 9.3.1; toolchain и посторонние зависимости не обновлять. Если resolver обнаружит реальный конфликт, подобрать совместимый выпуск без апгрейда проекта и зафиксировать выбор до реализации адаптера.

URL открывать режимом внешнего приложения, без встроенной browser view; для HTTP(S) это системный браузер. Web открывает новую вкладку по пользовательскому жесту. Приёмка должна подтвердить именно браузер: если системная ассоциация HTTP(S) перехватывает URL другим приложением, использовать browser-specific платформенный адаптер вместо молчаливого открытия этого приложения. Обработать результат/ошибку launch, не полагаться исключительно на `canLaunchUrl` и не открывать ничего при сетевой ошибке preview. Не запускать URL через shell-команду, собранную из пользовательского текста.

Поделиться означает файл проверенных исходных байтов, с MIME и расширением по фактическому формату. Android использует отдельный нативный адаптер через platform channel, системный chooser и временный content URI собственного закрытого FileProvider; macOS/Windows/iOS — доступный системный share. Linux — существующее сохранение; Web — Web Share при наличии возможности отправить файл, иначе download. Отмена — отдельный исход, недоступная возможность — явный fallback «Сохранить изображение». Если ОС не сообщает результат доставки, интерфейс не утверждает, что другое приложение успешно приняло файл.

Android share_plus 13.3.1 не использовать: его prepareShareIntent удаляет ранее переданные файлы перед каждой отправкой, а grantUriPermission включает WRITE вместе с READ. Это противоречит сохранности файла для получателя и доступу только на чтение. Отдельный Android-адаптер сохраняет каждый файл в уникальном приватном подкаталоге, не удаляет предыдущие файлы при следующем share, выдаёт только временный FLAG_GRANT_READ_URI_PERMISSION и очищает просроченные файлы при запуске приложения по TTL до 24 часов. FileProvider разрешает URI только из выделенного share-cache; широкие storage permissions не вводятся. Неиспользуемые Android FileProvider и receiver share_plus исключить из merged manifest; share_plus применяется только на остальных поддерживаемых платформах. Собственный provider и необходимые компоненты точечно внести в `scripts/release/android_audit.py` и негативные тесты baseline. Существующие installer-компоненты и release-подпись не меняются. Отдельная нативная реализация ограничена Android; на остальных ОС сохраняется платформенный плагин и согласованный fallback сохранения. Уникальные пути, read-only grant, чтение предыдущего файла после повторного share и очистка по TTL проверяются тестами и Android QA receiver.

Источники на момент планирования: [url_launcher](https://pub.dev/packages/url_launcher), [share_plus](https://pub.dev/packages/share_plus). Документация share_plus явно различает передачу файлов и отправку текста, не поддерживает файлы Linux и описывает download fallback Web; это согласуется с выбранной владельцем политикой.

### 3. Прямые изображения, без зависимости от расширения

Сервис загрузки принадлежит текущему письму, не API-клиенту. Он принимает только проверенный HTTP(S) URI без userinfo, использует изолированный клиент без FFIDO Authorization/cookies/custom CA. На Web — credentials omit и без прикладного дискового кеша. Не пересылать чувствительные заголовки и не переносить авторизацию при редиректах. Каждый переход заново валидировать, HTTPS не понижать до HTTP автоматически.

Автоматически проверять первую порцию из 10 уникальных URL текущего открытого письма, максимум два запроса одновременно; остальные доступны кнопкой «Загрузить ещё». Для обычных страниц сначала ограниченный HEAD; при явном не-image MIME не скачивать HTML. Для image MIME, неизвестного MIME, image-пути и серверов без HEAD разрешён ограниченный streaming GET с анализом сигнатуры. Для неизвестного формата прочитать не более 64 КиБ пробных байтов и закрыть ответ; известную сигнатуру PNG/JPEG/GIF/WebP дочитать в пределах общего лимита и проверить полностью. Неподдерживаемый MIME/формат, HTML/SVG и повреждённые байты не исполняются.

Лимиты: 16 МиБ на ответ, 16 миллионов пикселей, сторона до 8192, три редиректа, 15 секунд на всю операцию включая HEAD/GET. Content-Length служит ранней проверкой; поток дополнительно подсчитывается независимо от заголовка. Ошибки содержат понятное состояние и ручной повтор; URL с query не попадает в диагностические логи. Не логировать тело письма или изображение.

Переиспользовать чистую проверку заголовков `uueImageInfo`, но установить локальные лимиты внешних изображений независимо от серверных UUE limits. До декодирования проверить размеры; preview декодировать вписанным в 1000×1000 без увеличения, первый кадр. На native используются обычные системные сетевые ограничения; Web CORS/mixed content или платформенный запрет HTTP не обходятся. В таких случаях исходная ссылка доступна браузеру, серверный proxy не добавляется. Альтернатива `Image.network` без собственного контроля отвергнута из-за неограниченного размера ответа и отсутствия общего проверенного файла для share.

### 4. Fullscreen, кеш и жизненный цикл

Добавить отдельный viewer route с InteractiveViewer, вписыванием изображения, zoom/pan и действиями закрытия/share/save. Нажатие URL всегда открывает браузер; нажатие preview — viewer. Использовать уже полученные проверенные байты, не перезапрашивать оригинал при каждом открытии/share. Передавать неизменяемый объект изображения с форматом, размерами и безопасным именем без query-токенов; MIME определяется форматом, не суффиксом URL. Fullscreen может декодировать изображение крупнее thumbnail в пределах лимита, но не хранит коллекцию полноразмерных декодированных картинок.

Кеш — память текущего сообщения с совокупным бюджетом 32 МиБ исходных байтов; вытеснение LRU, освобождение codec/images/recognizers и отмена запросов при закрытии/смене письма. Не вводить постоянную галерею или глобальный кеш URL между профилями. При вытеснении исходника preview показывает возможность повторной загрузки, share не обращается к уже освобождённым данным. Активный viewer удерживает своё проверенное изображение до закрытия. Late completions сверяются с ID письма, epoch и состоянием mounted.

На смене сессии закрыть viewer и очистить его ресурсы; Back/Escape/кнопка закрытия возвращают сохранённый экран без новых RPC прочитанности/истории. Платформенный share-адаптер создаёт только приватные временные файлы с безопасным именем, удерживает их достаточно для чтения получателем и удаляет просроченные при следующем запуске (TTL до 24 часов). Не удалять файл сразу после открытия chooser; не выдавать доступ к всему cache root. Уже переданную по явному выбору пользователя копию внешнего приложения отозвать невозможно; это не считается кешем нового профиля FFIDO.

### 5. Совместимость и проверки

Backend/gRPC/JAM не меняются: функция обрабатывает существующее строковое body; все текущие типы областей читаются по прежним правилам. Ссылки не добавляют отправку/пересылку и не меняют server-side footer. Существующие UUE-превью и сохранение остаются под действующими ограничениями/правами; новые fullscreen/share предназначены для изображений по URL.

Unit-тесты разбора и ресурсных лимитов использовать без сети; fake HTTP с потоками/редиректами — для загрузчика. Widget-тесты проверяют точный текст/цитаты/выделение, клавиатуру, маршруты, ошибки, поздние ответы и платформенные исходы через внедряемые adapters. Android-приёмка включает реальное открытие браузера и передачу файла тестовому приложению-получателю с проверкой MIME/байтов/content URI; mock вызова плагина этого не заменяет. Desktop/Web отдельно проверяют доступный share или честное сохранение. Сборки и аудит ordinary main-target APK обязательны, QA receiver/entrypoint не включаются в обычный пакет.

## Risks / Trade-offs

- Автоматические preview обращаются к внешним сайтам при чтении → порции и параллелизм ограничены, FFIDO-секреты не передаются, загрузки отменяются при уходе; HTML metadata не запрашивается отдельно.
- URL без расширения и плохой HEAD → ограниченный GET/sniff, контроль полного объёма и времени; ложное изображение не декодируется как HTML.
- CORS, mixed content, недоступный системный share → ошибка preview с исходной ссылкой либо согласованное сохранение; проверки платформы не отключаются.
- Gesture recognizers могут мешать выделению → отдельный reader от редактора и regression-тесты copy/selection/FTN.
- Android share-адаптер и зависимость плагина меняют manifest → проверить merged provider/cache paths, отсутствие неиспользуемых компонентов share_plus и разрешения на запись, обновить только необходимый audit baseline и проверить signed APK на API 24/25/35.

## Migration Plan

Изменение только клиента, без миграции серверных данных и без обязательного обновления backend. Зависимости/registrants меняются штатными Flutter-командами; прочие настройки профилей не мигрируют. Для отката достаточно предыдущего клиента; новая функция не изменяет body/JAM и не оставляет обязательного состояния, временные share-файлы удаляются по TTL. Публикация и повышение версии выполняются отдельным запросом после реализации и проверки.
