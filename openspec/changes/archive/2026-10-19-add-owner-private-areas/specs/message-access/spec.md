# Spec Delta

## MODIFIED Requirements

### Requirement: Пересылка в выбранную эху
Из доступного для чтения эхописьма пользователь MUST иметь возможность переслать редактируемую копию в выбранную доступную для публикации эху. Редактор MUST явно показывать назначение, исходную эху и автора. Пересылка MUST создавать новое письмо без межконференционной reply-ссылки и сохранять действующие правила идемпотентности и обработки ошибок.

#### Scenario: Другая эха и право только на отправку
- **WHEN** у пользователя есть чтение исходной эхи и право публикации в другой эхе, включая право без чтения назначения
- **THEN** он может выбрать назначение, увидеть и изменить пересылаемый текст, добавить комментарий и отправить одно письмо в назначение
- **AND** право публикации в исходной эхе для этого не требуется

#### Scenario: Пагинация выбора и запрет назначения
- **WHEN** разрешённое назначение находится после первой страницы списка конференций
- **THEN** его можно найти и выбрать
- **WHEN** назначение не разрешает публикацию или право отозвано перед отправкой
- **THEN** недоступное назначение нельзя выбрать, либо сервер отклоняет отправку с сохранением черновика и без ложного успеха

#### Scenario: Подготовка и неопределённый результат
- **WHEN** пользователь отменяет выбор эхи
- **THEN** письмо не отправляется
- **WHEN** подтверждение отправки потеряно
- **THEN** повтор использует тот же ключ, назначение и тело без дубля; редактирование и смена назначения блокируются до разрешения неопределённости

#### Scenario: Приватная область
- **WHEN** владелец читает NetmailArea, LocalArea, BadArea, DupeArea или RobotsArea
- **THEN** действие пересылки в эху отсутствует, а приватные области не предлагаются как назначения эхопересылки

## ADDED Requirements

### Requirement: Тип области в интерфейсе
API SHALL передавать назначение области, формат хранения, доступность и разрешённые действия. Клиент SHALL отделять эхи, личную почту, локальные и служебные области, сохранять эти признаки в кеше и не трактовать неподдерживаемую базу как пустую эху. Тип для записи SHALL определяться сервером по области, а не полем клиента.

#### Scenario: Редактор по назначению
- **WHEN** владелец открывает поддерживаемую NetmailArea или LocalArea
- **THEN** интерфейс показывает соответственно личный либо локальный режим и разрешённые действия, без пояснения о публикации для всех участников эхи
- **WHEN** выбран служебный или неподдерживаемый тип
- **THEN** редактор отправки недоступен

#### Scenario: Смена пользователя и обновление кеша
- **WHEN** после владельца входит обычный поинт либо обновляется схема кеша
- **THEN** старый кеш не показывает личные области, их содержимое или статистику в новом контексте
