# Design

## Context

Мотивация — в `proposal.md`. `MessageService::GetMessages` уже принимает query и сортирует по паре дата/номер, но ищет регистрозависимо по теме, имени автора и телу. `JamMessageBase::ReadMessage` уже декодирует тело и текстовые подполе в UTF-8 по CHRS/default/override. Повторного декодирования не требуется. `Detail` формирует видимый текст, восстанавливает подтверждённый адрес получателя и читает персональное состояние; `GetMessage` дополнительно фиксирует просмотр.

`MessageRepository.getConferenceMessages` передаёт query, но `MessageScreen` не предоставляет поисковый UI. Экран содержит обычную навигацию по непрочитанным и межэховые переходы. `UueBody` скрывает UUE и вставляет изображения; `MessageLinkText` объединяет FTN-цитаты, ссылки и выделение. Эти пути нужно сохранить.

## Goals / Non-Goals

**Goals:** единый серверный алгоритм поиска и определения диапазонов; один согласованный текст результата; отсутствие прочитанности у пропущенных сообщений; явное разделение «Найти далее» и обычного листания.

**Non-Goals:** изменение старого query-фильтра, полное Unicode case folding всех языков, индексирование базы, поиск по всем эхам, поиск внутри декодированных бинарных вложений. Поиск выполняется в доступном тексте письма, включая исходный UUE. Новые зависимости и миграции не нужны.

## Decisions

### 1. Отдельный FindMessage RPC

В `contracts/ffido/v1/ffido.proto` добавить `FindMessage`: запрос содержит conference_id, UTF-8 query, обязательный режим HEADER_ONLY/HEADER_AND_BODY, сортировку, необязательный стартовый generation-qualified message_id и флаг include_start. Без стартового ID обход начинается с начала текущего порядка. Неизвестные enum и недопустимые параметры отклоняются, нулевые значения новых enum не означают скрытый default.

Ответ содержит необязательный полный `Message` и список `SearchMatch` (поле FROM_NAME/FROM_ADDRESS/TO_NAME/TO_ADDRESS/SUBJECT/BODY, start_utf16, length_utf16). Отсутствующее Message означает успешное достижение конца. Найденное письмо имеет обычную подтверждённую прочитанность и position_revision. Диапазоны отсортированы по полю и позиции, неперекрывающиеся и относятся ровно к строкам возвращённого Message.

В отличие от расширения `ListMessages`, RPC не требует вычисления total и всего списка совпадений перед открытием первого. Возврат текста и диапазонов одним ответом устраняет рассогласование отдельного поиска и последующего GetMessage. Старые методы и их контракты остаются неизменными.

### 2. Серверное сопоставление и единицы диапазонов

Переиспользовать политику `MessageEncoding` из `JamMessageBase.h` и эффективный override области; не выводить кодировку только из CHRS. При необходимости открыть внутренний read-only доступ к вычисленной кодировке без изменения файлов базы.

Алгоритм проходит валидный UTF-8 по Unicode scalar values, приводит ASCII A–Z, русские А–Я и Ё к нижнему регистру; прочие символы сохраняет. Только для эффективной CP866 дополнительно сводит н/h, р/p, у/y к общему представлению. Для запроса и каждого поля применяется одна и та же политика конкретного письма. Каноническая Unicode-нормализация и ё=е не применяются. Нормализация поиска не изменяет сохранённый текст.

Сохранять отображение нормализованных позиций на исходные UTF-16 code units, включая surrogate pair emoji. Сопоставлять буквальную подстроку и возвращать все неперекрывающиеся совпадения слева направо. Это убирает необходимость дублировать правила CP866 в Dart и позволяет применять диапазоны к `TextSpan` напрямую. Поля проверяются по отдельности на видимом представлении `Detail`, включая восстановленные адреса и DisplayText, а не на сыром теле до преобразований.

### 3. Обход и фиксация просмотра

Проверить права через существующий EchoAccess до чтения области. Получить согласованный список номеров и порядок `(date_written, number)` как у `GetMessages`, с обратным порядком для newest. Якорь проверить в текущей области и поколении независимо от наличия совпадения. Пройти от якоря включительно/исключительно по запросу, останавливаясь на первом совпадающем письме. Пропущенные кандидаты проверять read-only, без вызовов GetMessage/MarkRead.

Извлечь общий внутренний шаг фиксации просмотра из текущего `GetMessage` и использовать для найденного `Detail`, пока действует тот же JAM lease. Не открывать вторую lease рекурсивным вызовом GetMessage. Вернуть тот же текст, для которого вычислены диапазоны, с актуальным read-state и серверной ревизией. При ошибке фиксации не возвращать успешное открытие. Права, generation, deadline/cancellation и ошибки хранилища обрабатывать по существующим правилам. Проверять deadline и cancellation при обходе кандидатов и длинных текстов; освобождать lease при отмене.

Линейный обход без постоянного индекса выбран для минимального вмешательства в существующую архитектуру. Длительный поиск может закончиться deadline: это явная ошибка с повтором с прежнего якоря, а не «ничего не найдено». Скрытых фоновых задач и бесконечных автоматических повторов нет.

### 4. Состояние поиска в клиенте

На `MessageScreen` добавить диалог с подтверждением Enter/кнопкой, по умолчанию HEADER_AND_BODY; запуск не выполняется на каждом вводимом символе. Кнопка и Ctrl+F/F6 открывают диалог с последним запросом. Во время поиска доступна отмена; конкурирующие чтение, переход, отправка и отметки блокируются, закрытие экрана отменяет запрос.

Состояние включает запрос/режим/сортировку, стартовый якорь, последний найденный ID, диапазоны и ревизию локального запроса, связанную с session epoch и conference_id. Повтор без изменения контекста использует последний результат эксклюзивно; первый запуск или изменение параметров — текущее письмо включительно. Отмена/ошибка не продвигают якорь. При ручном выборе письма, обычной навигации, входе в цепочку, смене области или сортировки снимаются диапазоны и сбрасывается продолжение. Сами запрос и режим сохраняются в памяти текущего экрана, не синхронизируются и не сохраняются между профилями.

Результат открывается напрямую из ответа без второго GetMessage. Для связи с обычным списком при необходимости загрузить страницу через существующий `anchor_message_id`, не меняя контракт обычной навигации. Поиск из цепочки открывает результат в контексте всей области и сбрасывает threadId только при успешном результате. Отсутствие результата сохраняет текущее письмо/цепочку и снимает прежнюю подсветку; «Найти далее» не переходит в другую эху. Обычные кнопки «Предыдущее»/«Следующее» сохраняют свои требования `message-access`.

### 5. Подсветка поверх существующего отображения

Применить фон совпадений к заголовкам и текстовым spans, сохраняя цвета уровней цитат, recognizer ссылки, выделение и точное содержимое. При разбиении тела на сегменты для изображений/UUE переносить исходные смещения UTF-16 в каждый сегмент; не искать независимо по обрезанным фрагментам. При совпадении в скрытом UUE автоматически включать существующий просмотр исходника.

После раскладки прокрутить к первому диапазону через реальную геометрию текста, учитывая переносы, масштаб шрифта, заголовки и вставленные preview. Не оценивать позицию количеством строк. Поздняя загрузка изображений не должна уводить первое совпадение до завершения начального позиционирования или возвращать пользователя после его ручной прокрутки. На широких и узких экранах проверить одинаковый текст и доступность результата. Недопустимые диапазоны ответа считать ошибкой контракта, не применять к произвольной строке.

## Risks / Trade-offs

- Большие JAM-базы требуют линейного чтения под lease → ранняя остановка, проверки отмены/deadline, только одно письмо в ответе; индекс рассматривать отдельно по реальным замерам.
- Ошибки смещений в UTF-8/UTF-16 и разбиении UUE → серверные и widget-тесты с emoji, ссылками, вложенными цитатами и скрытым блоком.
- Отмена после фиксации чтения → не обещать откат, как для обычного GetMessage; поздний ответ не применяется к новой сессии.
- Полный Unicode case folding потребовал бы новых таблиц/зависимостей → явно ограничить нечувствительность регистром ASCII и русского, остальные символы сопоставлять буквально.
- Отсутствие версии snapshot между отдельными поисками → каждый повтор использует актуальную область и проверенный generation-qualified якорь; удалённый якорь даёт ошибку без молчаливого перезапуска.

## Migration Plan

Сначала обновить сервер, затем клиент. Перегенерировать Dart bindings штатным `tools/proto/generate.sh`, проверить `--check`; C++ bindings собираются штатным CMake. Новый клиент при UNIMPLEMENTED показывает необходимость обновления и не выполняет fallback через GetMessage для всех писем. Старые клиенты работают по прежним RPC. Откат не требует миграции SQLite или JAM: недоступна только новая функция, серверные отметки найденных писем остаются обычным персональным состоянием.
