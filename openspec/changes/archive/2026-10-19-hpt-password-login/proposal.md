# Proposal

## Why

Ручная выдача и ввод токена непонятны пользователю FTN и дублируют уже настроенные учётные данные HPT. Нужен вход по имени, FTN-адресу и паролю с сохранением сессии и возможностью продолжать работу на телефоне и ноутбуке.

## What Changes

- Форма подключения содержит имя, FTN-адрес, пароль и HTTPS-адрес сервера FFIDO; токены полностью скрыты из пользовательского интерфейса.
- Сервер читает HPT отдельным служебным процессом, исключает виртуальные линки и проверяет адрес линка и SessionPwd из конфигурации HPT; только при отсутствии SessionPwd используется Password. Пустой пароль запрещён.
- После проверки сервер выдаёт внутреннюю сессию; нативные клиенты безопасно сохраняют её для следующих запусков, не сохраняя пароль HPT.
- Несколько независимых сессий одного адреса используют общие профиль, прочитанность, закладки и историю. Второй клиент получает изменения при возврате в приложение и обновлении.
- **BREAKING**: заранее выданный токен больше не является способом входа; клиент и сервер обновляются согласованно. Существующие личные данные сохраняются через однозначное сопоставление FTN-адреса.
- Документируется подключение Android и ноутбука к публичному FFIDO на VPS с доверенным TLS-сертификатом.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `user-identity`: вход по данным HPT, внутренние независимые сессии, сохранение входа, доверенный отправитель, миграция идентичности и работа с двух устройств.
- `api-transport`: RPC входа, восстановления и завершения сессии с одинаковой семантикой gRPC/gRPC-Web.

## Impact

Затронуты `apps/frontend/` (настройки, API, запуск, кеш и безопасное хранение), `apps/backend/` (конфигурация, AuthService, gRPC, SQLite, администрирование), `contracts/ffido/v1/ffido.proto`, тесты, README и инструкции в `docs/`. Для точного чтения HPT используется совместимая библиотека fidoconfig установленной инфраструктуры; для нативного хранения сессии потребуется средство защищённого хранилища Flutter. Версии существующих зависимостей не обновляются.

Вне объёма: Binkp-клиент, регистрация и выдача FTN-адресов, изменение HPT/мейлера, push-синхронизация, синхронизация черновиков и позиции прокрутки, добавление Netmail. Отправка в сеть по-прежнему зависит от существующих HPT и мейлера.
