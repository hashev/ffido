# Spec Delta

## MODIFIED Requirements

### Requirement: Preview изображений по прямым ссылкам
В теле прочитанного письма SHALL автоматически появляться компактные preview прямых PNG/JPEG/GIF/WebP URL в пределах доступных платформенных сетевых возможностей. Расширение SHALL не быть единственным критерием: ссылки без расширения распознаются по ответу и фактическим байтам. Исходная ссылка SHALL оставаться доступной для браузера. HTML-страницы, SVG и прочие форматы SHALL не превращаться в preview изображения.

#### Scenario: Ссылка без расширения
- **WHEN** URL с query-параметрами без расширения возвращает корректный JPEG
- **THEN** клиент показывает его preview и сохраняет исходный URL для перехода во внешний браузер

#### Scenario: Ложное расширение или ошибка
- **WHEN** `.png` возвращает HTML, SVG или другой подтверждённый неподдерживаемый ресурс
- **THEN** клиент оставляет кликабельную ссылку без карточки, ошибки изображения и кнопки повтора

#### Scenario: Ошибка вероятного изображения
- **WHEN** путь URL имеет расширение PNG/JPEG/JPG/GIF/WebP без учёта регистра либо ответ уже подтвердил поддерживаемый тип изображения, но сеть, TLS, ограничения платформы, лимит или повреждённые данные мешают загрузке
- **THEN** клиент показывает контролируемую ошибку и явный повтор у исходной строки; исходный текст и ссылка доступны, браузер автоматически не открывается
- **AND** подтверждённый неподдерживаемый тип ответа имеет приоритет над расширением и скрывает карточку

#### Scenario: Повторы и большой список
- **WHEN** URL повторяется в письме либо число ссылок превышает автоматическую порцию
- **THEN** одинаковое изображение не загружается и не показывается многократно, оставшиеся ссылки доступны через явную загрузку следующей порции

## ADDED Requirements

### Requirement: Карточки только для ссылок на изображения
Клиент SHALL отделять проверку ссылки от карточки изображения. Обычная или ещё не классифицированная ссылка SHALL оставаться кликабельным текстом без карточки, пустого места, индикатора загрузки и повтора. Готовое preview SHALL появляться только после проверки поддерживаемых байтов и декодирования. Ошибка SHALL показываться только для вероятного изображения при отсутствии подтверждения неподдерживаемого ресурса.

#### Scenario: Обычные страницы и Origin
- **WHEN** письмо содержит `https://башорг.рф/quote/470067`, `https://wfido.ru` или `https://github.com/hashev/ffido`, и ответы являются HTML
- **THEN** все адреса остаются кликабельными, карточек и кнопок повтора изображения нет, включая адрес в Origin

#### Scenario: Сетевая ошибка обычной ссылки
- **WHEN** адрес без расширения поддерживаемого изображения не удаётся проверить из-за сети, TLS, CORS или тайм-аута и тип изображения не подтверждён
- **THEN** клиент оставляет только исходную ссылку без карточки ошибки изображения

#### Scenario: Распознавание без расширения
- **WHEN** проверяется URL без расширения, который возвращает корректное поддерживаемое изображение
- **THEN** до распознавания карточки нет, после проверки preview появляется под исходной логической строкой ссылки

#### Scenario: Смешанное письмо
- **WHEN** письмо содержит обычную страницу, прямой JPEG с query и fragment, повтор JPEG и ссылку в Origin
- **THEN** показывается одна карточка JPEG у первого вхождения, все ссылки кликабельны, исходный текст и копирование сохраняются

#### Scenario: Ограниченная проверка
- **WHEN** письмо содержит много обычных ссылок и изображений
- **THEN** скрытая проверка соблюдает действующие порции, лимиты параллелизма, времени, редиректов и байтов; смена письма отменяет её и исключает поздние карточки
