# Design

## Context

Мотивация — в proposal.md. До реализации MessageService::GetMessages вызывает GetMessageNumbers, затем читает и сортирует заголовки по дате. GetMessageNumbers в header-only реализации `apps/backend/include/JamMessageBase.h` читает каждый живой заголовок и сверяет результат с active_msgs. Поэтому повторное использование этого метода нарушит требование курсора не читать заголовки на нём и ниже.

ConferenceService получает статистику после JamAccess::Open; лёгкая ветка возвращает её без открытия базы. GetArchiveThread делегирует GetThread. ReadArchiveMessage уже применяет персональное сворачивание и не вызывает RecordView. GetMessageTechnicalData читает ReadRawMetadata, но отдаёт только LoID 4, 5 и 2000. Его выборку менять не требуется. gRPC mapping выполняется в `apps/backend/src/service/grpc_service.cpp`; domain-ответы должны донести новые поля до него.

В затрагиваемых файлах есть чужие незавершённые изменения, включая JAM и сервисы. План основан на текущем дереве; реализация должна сохранить их и перед началом перепроверить diff.

## Goals / Non-Goals

Цель — обеспечить контракт из трёх delta-спецификаций без изменения прежних веток запросов, архитектуры и протокола ffido.v1. Не входят: UI, локальный офлайн-кеш, автоматический sync-клиент, новые RPC, рефакторинг, изменение генерации message_id, миграции БД и расширение GetMessageTechnicalData.

## Decisions

### Один источник поколения

Расширить domain Conference/MessageListResponse/ThreadListResponse и соответствующий mapping. Копировать `JamAccess::generation()` из того же открытого доступа, который дал данные ответа: это в точности префикс message_id до `#`. Заполнять ListMessages, GetThread и GetArchiveThread, включая ранние успешные возвраты и пустые страницы. Conference получает поле вместе с известной статистикой; при statistics_known=false поле пусто, omit_statistics сохраняет ранний возврат без открытия JAM.

Не вычислять generation из total_count/last_message_date и не вводить отдельную версию для sync: замена базы с совпадающей статистикой должна отражаться ровно как в message_id. Межзапросный снимок не обещается; сохраняются текущие блокировки, cancellation и lifetime JamAccess.

### Отдельная ветка ListMessages по номеру

В gRPC и service передать новый sort и after_message_id; проверки сортировок FindMessage/SearchArchiveMessages оставить закрытыми для значения 3. До обхода проверять page, сочетания query/anchor/after/offset. Синтаксис курсора разбирать строго с проверкой числового переполнения. Не использовать разрешение существующего письма через MessageNumber как проверку курсора: удалённый номер допустим, а несовпадение поколения здесь должно дать FAILED_PRECONDITION (в отличие от существующих операций, например SearchUueParts).

Добавить небольшой helper диапазона в JamMessageBase: получить границы из base_msg_num и числа слотов индекса, перечислять только диапазон после курсора с проверкой живых заголовков внутри него. Проверять пустой индекс и сложение в расширенной арифметике. Для total использовать существующий счётчик живых сообщений active_msgs; не запускать GetMessageNumbers ради его пересчёта на курсорной ветке. Сохранить действующие проверки целостности читаемых записей, лимиты и отмену.

Без курсора offset пропускает живые сообщения в порядке номеров. С курсором offset=0, actual_offset=0; пропуск удалённых слотов не расходует limit. Для has_more искать следующий живой элемент после страницы, не сортируя даты. Не читать заголовки на курсоре и ниже даже для total, проверки удалённости курсора или построения всей коллекции. Сохранять существующие previews, ACL и respect_personal_filters; персональное сворачивание не меняет порядок и total. Не вызывать RecordView и операции записи metadata.

Альтернатива сортировки результата GetMessageNumbers отвергнута: она читает старые заголовки. Отбор по датам не обеспечивает позднее поступление старого письма.

### Полные подполя только по явному запросу

Расширить domain ArchiveMessage и ReadArchiveMessage, затем mapping ответа. При include_subfields && body_offset!=0 возвращать Validation/INVALID_ARGUMENT. После проверки доступа, точного reference и сворачивания читать ReadRawMetadata из того же JamAccess для первой части нескрытого письма и переносить все subfields без фильтра LoID, декодирования, нормализации или удаления пустых значений; attributes2 копировать без изменения битов. При reveal=false и collapsed оставить новые поля пустыми/нулевыми; include_subfields=false не добавляет raw-чтение. Существующий общий лимит блока 64 КиБ сохраняется, превышение обрабатывается текущей ошибкой JAM.

Повторный вызов GetMessageTechnicalData не подходит: он фильтрует подполя и не учитывает требуемую семантику collapse этого ответа. Изменять его поведение не нужно.

### Совместимость и генерация

Добавить только перечисленные поля с заданными номерами и enum 3; комментарии attributes уточняют raw JAM, Local=0x1, Private=0x4, а не FTS-0001. Login и RestoreSession устанавливают supports_offline_sync=true аналогично текущим флагам. Старые клиенты игнорируют новые поля, старый сервер даёт false по умолчанию; использование opt-in возможностей возможно только при поддержке. Доставка Dart-моделей входит в объём, внедрение sync в UI — нет.

Генерировать Dart только `tools/proto/generate.sh` с закреплённым protoc 36.2 и protoc_plugin из tools/proto; C++/descriptor — штатной CMake-сборкой. Не править generated вручную и не обновлять зависимости.

## Risks / Trade-offs

- Чтение старых заголовков через общий helper → отдельная диапазонная ветка и storage-тест с наблюдением номеров реально прочитанных заголовков через минимальный тестовый seam либо изолированный fixture, делающий такое чтение обнаружимым.
- Ошибка границ/переполнение/удалённый крайний слот → unit-тесты base_msg_num, последнего слота, пустого индекса, удалённых номеров и числового переполнения.
- Утечка скрытых подполей → сервисные и gRPC-тесты collapsed/reveal, включая ненулевой attributes2.
- Ложная инвалидизация по дате/счётчику → замена базы с прежними total/date и сверка generation с message_id во всех ответах.
- Случайная запись персонального состояния → снимки read_status, history и reading_positions с ревизиями до/после каждого нового режима, включая ошибки.
- Сырые bytes и крупный блок → round-trip с NUL, невалидным UTF-8, high_id, повторами, пустыми значениями, границей 64 КиБ и превышением; прежние RPC-лимиты сохраняются.

## Migration Plan

Миграции данных нет. После проверок сервер и Dart stubs можно доставлять независимо благодаря аддитивному protobuf; новый клиент проверяет флаг перед использованием новой семантики. Откат на старый сервер убирает capability; старые запросы продолжают работать. Развёртывание и коммит требуют отдельного запроса.


## Итоговая сверка (2026-11-15)

Реализованы все 19 задач; текущие результаты приёмки приведены в docs/testing.md.
Поколение сохранило прежнее определение JamAccess. Физическая замена файлов
по-прежнему требует штатного переоткрытия каталога: до него сохраняется отказ,
после него все успешные ответы отражают новый префикс ID при прежних count/date.
Межзапросного снимка нет; курсор ListMessages допускает добавление новых больших
номеров, а поисковое архивное продолжение сохраняет собственные правила
инвалидации. Полные raw-подполя не меняют GetMessageTechnicalData и не добавляют
чтение при include_subfields=false. UI и sync-клиент не входят в изменение.
