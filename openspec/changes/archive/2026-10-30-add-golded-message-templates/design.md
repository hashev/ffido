# Design

## Context

Мотивация — в `proposal.md`. Исследован локальный GoldED+ 1.1.5 из `/Users/yurik/Downloads/golded-plus-1.1.5-20260425-source`:

- `golded3/getpls.cpp:TemplateToText` — условия строк, команды заголовков, include, random, quote и message; `getpls.h` — встроенный шаблон.
- `golded3/gemsgs.cpp:TokenXlat` и `tokenxchg` — подстановки, выбор альтернатив `{...}`, `@@`, align/pad/tr и pipe.
- `golded3/gcmisc.cpp:CookieIndex` — блоки random; `golded3/geline.cpp` — обработка `@position`.
- `golded3/gccfgg8.cpp:CfgTemplate` — выбор файла шаблона и сопоставление адресов; `cfgs/template/default.tpl`, `golded.tpl`, `rusCP866.tpl` — примеры.

Наблюдаемое поведение: условия относятся к строке, могут сочетаться и распознаются без учёта регистра. `@reply` и `@quoted` — разные режимы; `@include` делает только TokenXlat содержимого, не рекурсивный TemplateToText. Random использует текстовый файл и необязательный бинарный индекс `.mdx`; блоки разделены пустыми строками, `+` означает пустую строку внутри блока. GoldED включает функции внешних программ и локальной базы, которым нет соответствия в FFIDO.

В FFIDO `apps/frontend/lib/pages/message_screen.dart` инициализирует тему, адресата и тело в редакторе: ответ через `quoteReply`, пересылка через фиксированную шапку. `lib/utils/ftn_text.dart` задаёт действующие Unicode-правила цитирования. `lib/pages/settings.dart` хранит оформление через `MessageFooterSettings`/SharedPreferences и участвует в guardExit обновлений. `lib/models/message.dart` содержит имена, адреса, дату и тело, но не полный набор FTN-заголовков GoldED. В `contracts/ffido/v1/ffido.proto` и бэкенде отправитель определяется профилем; имя нельзя независимо заменить в запросе отправки. В проекте уже есть file_selector и файловые адаптеры для Web/нативных платформ.

## Goals / Non-Goals

**Goals:** единый переносимый интерпретатор с проверяемой семантикой GoldED, локальное хранение редактируемого текста, отсутствие повторной генерации черновика, сохранение текущего API.

**Non-Goals:** эмуляция экранного редактора, печати и хранилищ GoldED; перенос его конфигурации, системных программ и отправителей; побайтовое воспроизведение ошибок, ограничений DOS и OEM-ширины символов.

## Decisions

### 1. Совместимость определяется явным реестром конструкций

Предлагается чистый Dart-модуль `apps/frontend/lib/templates/` с разбором строк, токенов и параметров, единым реестром для исполнения, валидации и справки. Альтернатива — последовательные replace/regexp — не позволяет надёжно различить `@@`, параметры, условия и текст данных. Не копировать C++ GoldED: реализовать семантику независимо, проверять на коротких собственных примерах, сохранять ссылки на изученные функции.

Матрица целевого профиля:

| Группа | Решение FFIDO |
|---|---|
| `@new`, `@reply`, `@quoted`, `@forward`, `@notforward`, `@net`, `@echo`, `@local` | Полная построчная фильтрация, включая сочетания и регистр |
| `@changed`, `@moved`, `@comment`, `@quotebuf`, `@write`, `@header` | Распознавать как неактивные режимы с информационной диагностикой; не объединять с reply/quoted |
| `@moderator` | Проверка наличия `moderator` в имени текущего отправителя, как в GoldED |
| `@quote`, `@message`, `@position` | Цитата для quoted, тело оригинала для forward, маркер курсора; остальное по спецификации |
| `@setsubj`, `@forcesubj`, `@setto`, `@forceto` | Порядок строк GoldED; set меняет пустое значение, force всегда; снятие внешних кавычек; только тема и имя адресата |
| `@include`, `@random` | Неподдерживаемые файловые директивы; явная блокирующая диагностика |
| `@oname/@ofname/@olname/@oaddr/@o3daddr`, `@dname/@dfname/@dlname/@daddr/@d3daddr` | Отправитель и получатель оригинала; варианты имён `{me}{you}{all}` и `{domain}` для адресов при наличии домена |
| `@cname/@cfname/@clname/@caddr/@c3daddr`, `@fname/@ffname/@flname/@faddr/@f3daddr`, `@tname/@tfname/@tlname/@taddr/@t3daddr` | Текущий профиль, отправитель и получатель черновика; отправитель неизменяем |
| `@pseudo/@tpseudo/@fpseudo/@cpseudo/@opseudo/@dpseudo` | GoldED-семантика первого слова и альтернатив; без адресной книги/пользовательских nickname; отсутствие псевдонима поясняется |
| `@oecho/@odesc/@cecho/@cdesc` | Исходная и текущая области; при новом письме исходная область равна текущей |
| `@odate/@otime/@odtime/@otzoffset`, `@cdate/@ctime/@cdtime/@ctzoffset` | Дата оригинала и зафиксированный момент создания; формат даты `dd.MM.yyyy`, времени `HH:mm:ss`, сочетание через пробел; текущая зона устройства, отсутствие исходного FTN offset диагностируется |
| `@subject` | Исходная тема при reply/quoted/forward, текущая тема при new, как в TokenXlat; не путать с автоматически добавленным Re:/Fwd: |
| `@version/@ver/@rev/@pid/@longpid/@widepid/@osver/@osslash/@uptime` | Данные FFIDO и доступной платформы, время работы клиента; не выдавать FFIDO за GoldED; фиксировать значения в снимке |
| `@tagline/@tearline/@origin` | Текстовые значения существующих настроек, без самостоятельного изменения серверного footer; справка предупреждает о дублировании при явной вставке оформления в тело |
| `@align{column}{fill}`, `@pad{fill+alignment+width}{text}` | Заполнение/обрезка GoldED, L/R/центр; Unicode-символы вместо OEM-байтов; проверка размера до выделения памяти |
| `@tr{...}` | Диагностика отсутствующей таблицы TRANSLATE из golded.cfg; не притворяться совместимым без неё |
| `@setfrom/@forcefrom`, `@pipe`, `@attrib`, `@spellchecker`, `@xlatexport`, `@loadlanguage` | Распознанное ограничение с ошибкой: профиль сервера, программы ОС либо внутренние функции GoldED |
| `@msgno/@msgs`, `@omsgid/@omessageid`, `@ofrom/@oto/@cfrom/@cto`, `@dpgp/@fpgp`, `@attr`, `@areatype/@areapath/@areaname` | Диагностика недоступных либо несовместимых данных GoldED; не подставлять внутренний message ID FFIDO вместо FTN MSGID, не раскрывать/выдумывать путь серверной базы |
| Неизвестные конструкции | Ошибка с местом и рекомендацией `@@` для буквального текста |

Согласованное с пользователем исключение: команды ОС, специфичные функции GoldED и смена отправителя диагностируются. Максимальная совместимость означает поддержку переносимых данных и операций, а не обещание исполнения любого `.tpl`. Служебные неактивные строки не блокируют сохранение обычного GoldED-шаблона; активные неподдерживаемые команды/данные блокируют, пока пользователь не исправит их. Проверка рассматривает все поддержанные действия и области, а не только выбранный предпросмотр. Внутри неактивных режимов недоступные токены не считаются активной ошибкой.

Имена `c/f/t/o/d` сохраняют семантику GoldED: `c` — пользователь/текущий контекст, `f/t` — черновик, `o/d` — стороны оригинала. В новом письме поля отсутствующего оригинала дают пустые значения, дата оригинала отсутствует; это отражает предпросмотр и справка. Сравнение me/you/all — без учёта регистра, по имени профиля и адресата; множественных USERNAME и адресной книги GoldED нет. Параметры выбираются в порядке tokenxchg, более поздняя подходящая альтернатива имеет приоритет. Встроенные ограничения длины GoldED для имён/адресов воспроизводятся по Unicode-символам; не разрезать UTF-8 или surrogate pair. Это документированное отличие от OEM-байтов.

### 2. Хранится только текст

По уточнению пользователя подключение внешних файлов исключено. Нет ресурсов, file_selector, импорта кодировок или файлового random. Шаблон редактируется и вставляется через буфер обмена как Unicode. `@include` и `@random` распознаются и блокируют сохранение с понятным объяснением; это не неизвестный токен и не молчаливое игнорирование.

Один версионированный JSON-документ в SharedPreferences содержит текст. Отсутствующий ключ и явно сохранённый пустой текст различаются. Ограничения: 64 КиБ шаблона и 1 МиБ результата; глубина параметров до 16. Сохранять проверенный текст одной записью; при ошибке сохранять рабочую версию и введённый текст в форме. Откат не меняет footer/подключение.

### 3. Единый результат генерации и снимок черновика

Интерпретатор получает тип действия, тип/имя/описание текущей и исходной областей, оригинал, профиль, исходные заголовки и зафиксированное время. Возвращает тело, тему, имя адресата, offset курсора и диагностику. Никаких сетевых вызовов или изменений профиля. Подставленные данные оригинала/профиля и результат `@message/@quote` не интерпретируются повторно как команды: вложенное форматирование разбирается только из синтаксиса шаблона. Это намеренное отличие от небезопасных повторных подстановок старого движка.

Сначала сформировать прежние тему и адресата, затем исполнить строки по порядку; изменения force/set отражаются в последующих подстановках. FTN-адрес получателя не выводить из `@forceto` и не менять автоматически. Новый ответ без цитаты выбирается до открытия редактора в компактном выборе вида ответа; действие «Ответить в эху» остаётся единым. Не давать переключатель, который незаметно перегенерирует уже изменённый черновик.

При открытии редактора дождаться загрузки настроек до разрешения редактирования, учитывая mounted и epoch сессии. Снимок настроек и момент времени фиксируются один раз. При смене области пересылки показывать, что оформление уже сформировано для исходного контекста; тему и тело не перегенерировать. UUE и кросспостинг получают уже сформированные поля. Не применять шаблон на уровне transport/repository sendMessage: повтор и отправка программно подготовленного текста должны оставаться неизменными. Существующие helper reply/forward в repository не шаблонизировать повторно.

Отсутствующий override использует прежнюю инициализацию, включая шапку пересылки; явно пустой override даёт пустое тело. В режиме пользовательского шаблона quoteReply используется для `@quote` с его существующими переводами строк; отдельная автоматическая цитата не добавляется. Пользователь выбирает её расположение, а не меняет алгоритм цитирования.

### 4. Настройки, предпросмотр и ошибки

В текущих настройках добавить блок «Шаблон писем»: многострочное поле, справку с матрицей поддержки, независимое сохранение/сброс и предпросмотр. Исходный текст сохранять с нормализацией переводов строк LF; комментарии и формат не переписывать. Предпросмотр использует тот же интерпретатор, фиксированный пример оригинала/профиля и переключатели действия/области, показывает тело, тему, имя/адрес получателя и курсор; примерные данные явно обозначены.

Ошибки имеют имя шаблона, строку, столбец, код и русское объяснение. Информационные сообщения для неактивных режимов и отличий не блокируют; ошибки параметров, файловых директив и неподдерживаемых активных функций блокируют сохранение. При повреждённом сохранённом документе предложить явно открыть редактор со штатным оформлением или вернуться к настройкам. Не выполнять молчаливый fallback с потерей пользовательского текста. Добавить несохранённый текст шаблона в существующий guardExit; сохранение не требует логина.

### 5. Совместимость API и оформления

API и бэкенд не меняются: имя отправителя принадлежит профилю, тело — обычный текст. Сохраняются серверная валидация, получатель исходящего netmail через replyName/replyAddress, in_reply_to, ограничения областей, footer snapshot, UUE и operation_id. Template не добавляет автоматический Tagline/Origin: существующий footer pipeline остаётся единственным источником автоматического оформления. Явные `@tagline/@origin` в теле не подавляют серверный footer и показывают предупреждение в предпросмотре. Альтернатива — управление серверным оформлением из шаблона — потребовала бы отдельного контракта и не входит в согласованный объём.

## Risks / Trade-offs

- [Редкие конструкции GoldED и параметры] → Матрица выше, собственные эталонные примеры для каждой группы, русская справка с ограничениями; не объявлять 100% совместимость.
- [Большой текст в SharedPreferences] → Лимит 64 КиБ и отказ без частичного сохранения.
- [Разница OEM и Unicode/часовых зон] → Unicode-текст из буфера обмена, Unicode-ширины и форматы дат, отсутствие выдуманных FTN offset; тесты кириллицы и emoji.
- [Задержка загрузки перезаписывает ввод] → Инициализировать до ввода один раз, проверять epoch/mounted, не перестраивать генерацию при setState.
- [Смена адресата и области меняет смысл приветствия] → Показывать сгенерированный текст для ручной правки; не уничтожать черновик автоматическим обновлением.
- [Несовместимые директивы в распространённых шаблонах] → Показать все проблемы до сохранения, не скрывать команды; поддержать неактивные служебные строки без блокировки.

## Migration Plan

1. Выпустить клиент без изменения протокола и требований к версии сервера; отсутствие ключа сохраняет прежнее поведение.
2. Пользователь вставляет `.tpl`, проверяет все режимы и сохраняет проверенный набор.
3. Сброс удаляет только пользовательский текст шаблона, не меняет оформление footer/подключение. Откат клиента игнорирует новый отдельный ключ; уже отправленные письма и открытые черновики не мигрируются.
