# Design

## Context

На изолированной копии `ru.photo` из 454 записей 20 содержат `CHRS: +7 FIDO 2`.
Первое проблемное письмо — №30. Заголовки, границы подполей и тела проверены
независимым разбором JAM. Официальный FFIDO 1.0.25 возвращает INTERNAL на чтении
всех 20 и на полном архивном поиске по теме и телу. Поведение воспроизводится
с кандидатом манифеста и без него. Поиск по периоду №454 с кандидатом успешен.
Резервная KOI8-R на изолированной базе в режиме override устраняет ошибку,
что локализует дефект в определении декодера.

`MessageEncoding` берёт первое слово из CHRS. Для этих записей получается
`+7`, который iconv в официальном контейнере отвергает. `ReadMessage` отображает
отказ в `kCorruptedData`, а `SearchArchiveMessages` завершает запрос на первом
письме с такой ошибкой. Этот путь вызывается даже при поиске только по теме.

В отдельной одноразовой копии замена только меток на CP866 имитировала
распознавание алиаса в старом бинарнике. Архивный поиск по теме и телу прошёл
четыре страницы и нашёл №454. С тестовыми поправками №30 и №281 сообщали
эффективный KOI8-R. Отпечатки этого эксперимента относятся к изменённой
одноразовой копии. Для кандидата нужно вычислить их заново по исходным байтам.

## Goals / Non-Goals

**Цели:** корректно распознавать устаревшую декларацию, показывать фактическую
кодировку чтения и вернуть полный поиск по копии `ru.photo`.
**За рамками:** автодетект, принудительная кодировка всей эхи, перепись JAM и
изменение контракта поиска при настоящем повреждении либо неизвестном CHRS.

## Decisions

1. Нормализовать два полных исторических обозначения в `MessageEncoding` до
   проверки конфликтов и до вызова iconv. Каноническое `+7_FIDO` означает CP866
   по [FTS-5003.001, §5](https://raw.githubusercontent.com/zoomosis/ftsc/master/fts/fts-5003.001).
   Написание с пробелом принимается для совместимости с обнаруженной историей.
   Проверять границы имени, регистр и пробельные разделители. Голый токен `+7`
   не получает нового значения. Равнозначные декларации не конфликтуют.
2. Разделить объявленную и фактическую кодировку. Для исторических записей с
   подтверждёнными байтами KOI8-R использовать существующую адресную поправку
   с ожидаемым декодером CP866 и SHA-256 исходных подполей и тела. Распознавание
   алиаса само по себе лишь сделает ошибочно маркированные письма доступными
   для чтения как CP866. Содержание требуется сверить независимо.
3. Сохранить контракт чтения, ошибки и приоритеты override, IBMPC, неизвестных
   CHRS и конфликтов. Для оператора различать отказ выбора декодера и ошибки
   структуры JAM. Диагностика содержит категорию, область и локальный номер
   при их наличии, без полей сообщения и байтов текста. Действующие gRPC
   поля технических данных достаточны для сырого CHRS и эффективного декодера.

## Risks / Trade-offs

- Любой неизвестный или конфликтующий CHRS по-прежнему может остановить
  полный поиск. Диагностика должна назвать причину, сохраняя действующее
  поведение RPC.
- Старый сервер не сможет применить новые строки с ожидаемым CP866 для
  `+7 FIDO`. Поэтому манифест и backend проверяются как пара и при откате
  совместно возвращаются к предыдущим версиям.

## Migration Plan

Прогнать чтение и поиск на официальной версии и сборке кандидата с одной
копией JAM. Подготовить новый манифест только после проверки фактических байтов.
На amster2 сначала сверить действующие строки и добавления с новым backend
через dry-run. Развёртывание и смена ссылки на манифест выполняются после
отдельного запроса. Для отката заранее сохранить образ, конфиг и манифест.
