# Design

## Context

Мотивация и согласованный объём — в `proposal.md`: источник нового сценария только EchoArea, назначения — NetmailArea и другая EchoArea.

В `apps/frontend/lib/pages/message_screen.dart` исходная область задаёт `widget.kind`, право обычного ответа проверяет `canPost`, а выбор `destination` применяется только при `forward=true`. Шаблон уже умеет отдельные текущую/исходную области и quoted/reply/net/echo. При отправке исходный ID включается в CreateMessage/UUE, если это не forward; footer и проверка Netmail частично зависят от типа исходной области. Поэтому простого добавления назначения к существующему ответу недостаточно.

`ForwardDestination` фильтрует только эхи. `ConferenceRepository.fetchAllConferences` умеет полный обход страниц и защиту epoch, но допускает fallback первой страницы кеша; `getConferenceById` выполняет актуальный GetConference. Модель Conference уже содержит kind, canPost, unsupportedFormat, storageFormat и personalMailbox.

Backend `MessageService::CreateMessage` требует только право записи при пустом in_reply_to; непустой ID разрешается исключительно в JAM назначения и создаёт локальную reply-связь/FTN REPLY. Netmail требует полного FTN-адреса, имени и совместимого адреса профиля/области. Личные ящики используют существующий транспорт и исходящую копию; разрешённые области уже ограничены сервером.

## Goals / Non-Goals

**Goals:** отдельный пользовательский сценарий с сохранением автора и редактируемой цитаты, явной аудиторией и безопасным повтором; переиспользование существующих API и шаблонов без изменения обычного ответа/пересылки.

**Non-Goals:** межобластное дерево ответов, FTN REPLY на оригинал другой базы, публичный ответ из приватного источника, новая маршрутизация Netmail, новый RPC/схема данных, адресный справочник и кросспостинг нового режима. Отправка в ту же эху выполняется прежним действием.

## Decisions

### 1. Самостоятельное исходящее письмо без расширения API

Использовать CreateMessage с conference_id назначения и пустым in_reply_to. Для явно выбранного UUE — прежний CommitUue с пустым in_reply_to. Нет команды пересылки в тексте: пользовательский смысл ответа задают автор как адресат, Re:, цитата и режим шаблона quoted/reply.

Это сознательно создаёт новую локальную цепочку. Отправлять ID исходной JAM в другую запрещено: совпадающий номер или generation может создать неверную связь либо ошибку. Добавление source_reference и межобластного FTN REPLY потребовало бы нового серверного контракта, проверки двух областей и правил восстановления; сохранение цитаты и адреса этого не требует. Существующий обычный ответ продолжает передавать своего родителя без изменений.

Снимок уже прочитанного оригинала используется для текста и полей черновика. Дополнительная серверная проверка источника при отправке не вводится: новый запрос содержит только обычный текст, а сервер проверяет целевую область. Новое действие требует доступного исходного письма при открытии; смена сессии очищает снимок.

### 2. Выбор назначения до создания редактора

«Ответить лично» загружает полный свежий каталог и оставляет только доступные JAM NetmailArea. Один кандидат выбирается автоматически, несколько — явно. «Ответить в другую область…» открывает выбор Netmail/других эх с видимыми типами и группировкой, исключая исходный ID, неподдерживаемые базы и canPost=false. Доступ на чтение назначения не требуется для обычной отправки при наличии canPost.

Для единственного Netmail нельзя делать вывод по первой странице, отфильтрованному поиску или кешу. В fetchAllConferences добавить необязательный параметр запрета fallback с сохранением прежнего default для остальных вызовов; новый selector использует свежий полный каталог. Локальный поиск применяется к загруженному результату, не меняя определение единственного ящика. Отсутствие Netmail и ошибка загрузки — разные состояния с понятным объяснением/повтором.

Переиспользовать разметку/механику существующего выбора назначения только в необходимом объёме: общий selector с явными допустимыми типами либо отдельный тонкий экран, использующий репозиторий. Не расширять правила текущей пересылки до Netmail. Смена пользователя, endpoint или закрытие экрана отменяет загрузку и исключает поздний результат.

### 3. Разделение источника, намерения и назначения

В редакторе явно выделить новый режим crossAreaReply, не использовать для него forward=true. Хранить неизменяемые original/source и выбранный destination. Ввести один источник данных для эффективных target ID/name/kind/description и признака обычной same-area reply-связи.

Все пути отправки, подпись footer, проверка адреса, подписи интерфейса и доступность кросспостинга должны опираться на фактическое назначение. Новый режим отправляет в одну область и не предлагает кросспостинг; старые режимы сохраняют существующий кросспостинг. Вызов создания редактора при source.canRead=true не требует source.canPost для нового режима.

Имя и адрес сначала берутся из original.fromName/fromAddress; для этого источника нельзя использовать правило Message.replyName/replyAddress, которое меняет корреспондента собственного исходящего Netmail. Тема получает Re: без дублирования префикса; цитата создаётся прежним quoteReply. Имя/адрес доступны для редактирования. При отсутствии корректного адреса Netmail требует ручного ввода; полные числовые адреса валидируются прежними правилами, без новой догадки по Origin/телу.

### 4. Шаблон и переключение аудитории

Создавать редактор после выбора назначения, чтобы TemplateContext сразу содержал destination.kind/area/description, source originalArea/originalDescription и оригинал. Выбирать quoted либо reply; forward/new не активировать. Условия net/echo отражают назначение. Ветка без пользовательского шаблона повторяет обычный ответ. Однократность и обработка повреждённого шаблона сохраняются.

«Изменить область назначения» сохраняет тело, тему, ручного адресата и файл. При Netmail → Echo показать отдельное подтверждение публичности с именем эхи до изменения состояния. При отмене ничего не меняется. После смены типа показывать пояснение, что шаблон уже применён и оформление стоит проверить вручную; не применять его повторно. Автоматический footer берётся по target.kind: echo — прежний механизм, netmail — без эхового footer. Пользовательский текст шаблона не очищается скрытно.

### 5. Предварительная проверка и неопределённая отправка

Перед первой/изменённой попыткой актуализировать destination через getConferenceById; подтвердить допустимый тип, отличающийся ID для эхи, JAM и canPost. Ошибка проверки не запускает отправку и не выбирает другое назначение. Последующая серверная проверка остаётся окончательной, включая AKA, кодировку и лимиты. Проверка полного адресата Netmail выполняется до upload UUE.

После подтверждённого отказа сохранять текст и позволять исправление/явную смену назначения. До новой операции смена назначения создаёт новый operation_id и сбрасывает только несостоявшиеся снимки отправки/footer/UUE; авторский текст не меняется. После неопределённого RPC блокировать редактирование, назначение и вложение; явный повтор использует тот же ключ и замороженные поля. Не проводить новую клиентскую предварительную проверку, способную заблокировать сверку неизвестного результата; сервер всё равно проверяет права по прежнему контракту.

После успеха оставаться у исходного письма, инвалидировать кеш каталога и обновлять счётчики штатным механизмом без открытия чужого локального ID в исходной эхе. Подтверждение по-прежнему «сохранено локально». Долговременного хранения черновика не добавлять.

## Risks / Trade-offs

- Смешение widget.kind исходной эхи и типа назначения → единые getter target и тесты каждой ветки text/UUE/footer/интерфейса; Netmail не получает эховую автоматику.
- Потенциальная публикация личного черновика → видимая аудитория и отдельное подтверждение Netmail → Echo, без автоматического fallback.
- Неполный или устаревший каталог → полный свежий обход перед автоназначением и актуальная проверка конкретного назначения до новой отправки.
- Смена области после применения шаблона → сохранение текста и явное пояснение вместо повторной генерации.
- Нет межобластной связи обсуждения → самостоятельная цепочка с сохранением цитаты/адресата; ограничение документируется, старые reply-связи сохраняются.
- Право canPost не гарантирует совместимость AKA/кодировки → прежний серверный отказ сохраняет черновик; настройки сервера не подменяются клиентом.

## Migration Plan

Изменения протокола, миграции SQLite/JAM и обновления серверного toolchain отсутствуют. Достаточно обновить клиент на уже поддерживаемом сервере с нужной областью. Если Netmail не настроен, личный ответ объясняет отсутствие назначения; другие эхи остаются доступны в общем выборе. Откат клиента не меняет сохранённые письма: они читаются как обычные самостоятельные письма в назначении. Backend меняется только в тестах/документации при необходимости подтвердить существующий контракт.
