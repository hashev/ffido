# Design

## Context

Мотивация — proposal.md. Подтверждённые места затрат:

- `reader_app.dart` в initState вызывает `fetchAllConferences` (страницы по 20), сортирует полный результат и повторяет загрузку после изменения закладки/чтения/активации вкладки.
- `ConferenceService::Describe` открывает JAM, перебирает номера и заголовки, проверяет прочитанность каждого письма. Даже сортировка `name` считает статистику каждой возвращаемой строки.
- `ListBookmarks` сначала вызывает GetConference для всех закладок, потом отрезает страницу. `AddBookmark` также использует GetConference со статистикой.
- `PersonalConferences.open` догружает все страницы исходного списка до открытия чтения. Источник переходов зависит от того, откуда открыли письмо.
- Матрицы build.yml и native-dependencies.yml включают macos-15-intel; settings.json требует восемь пакетов.
- Логи stable 1.0.21, run 41796160592: Intel pub cache hit, зависимости около 3 секунд, составной шаг pub get + Flutter tests — 835 секунд; ARM аналогичный шаг — 766 секунд. Повторное кеширование не доказано как решение. Нативные зависимости уже имеют отдельные проверяемые кеши.

## Goals / Non-Goals

**Goals:** стоимость первого показа зависит от страницы избранного, полный каталог не читает JAM; действия над строкой не запускают обход всех областей; навигация имеет один понятный источник. Сохранить существующие ACL, cancellation/epoch, приватность и серверную прочитанность.

**Non-Goals:** постоянный offline-кеш личной почты, фоновое чтение тел, новые правила отправки, глобальный индекс статистики JAM, предзагрузка полного каталога, обновление toolchain, замена механизма кеширования CI, сокращение тестов оставшихся платформ, релиз и развёртывание.

## Decisions

### 1. Один постраничный контракт с явным лёгким режимом

Совместимо расширить `ListConferencesRequest`: `omit_statistics` (по умолчанию false), `bookmarked_only` (false). Добавить вариант `ConferenceSort` для порядка UI: тип Netmail, Local, Bad, Dupe, Robots, Echo; внутри типа имя без учёта регистра, затем ID. Использовать один согласованный нормализатор/компаратор для серверного порядка и проверочных данных клиента, включая кириллицу; не добавлять зависимость ради сортировки. Прежние значения sort и отсутствие полей сохраняют старый контракт.

Новый сервер объявляет `supports_lightweight_conference_catalog` в `SessionInfo` (свободный номер поля после существующих). Новый клиент включает новые параметры только при этом признаке. Старый клиент с новым сервером работает как раньше; новый со старым использует существующие ListBookmarks и fetchAllConferences как явно медленный совместимый путь, скрывая счётчики общего списка. В таком пути сохраняются полный корректный порядок и избранность, без ложного обещания быстрого режима. Не отправлять новый enum старому серверу. Нет повышения protocol major или миграции базы.

Сначала получить доступные метаданные и пользовательские закладки, применить поиск/фильтр/порядок и пагинацию. В лёгком режиме не вызывать JamAccess, GetMessageNumbers/GetHeader, IsMessageRead: вернуть ID, имя, описание, тип, формат, ACL, избранность; statistics_known=false, счётчики/дата не измерены. В карточке это осознанное отсутствие счётчиков, а не надпись «Статистика недоступна». Неподдерживаемый формат сохраняет свою диагностику.

Для избранного новый клиент использует тот же контракт с bookmarked_only=true и статистикой только возвращаемой страницы. GetConference сохраняет точную статистику для точечного обновления. ListBookmarks также переносит расчёт статистики за отбор доступных закладок и пагинацию, сохраняя его прежний порядок added_at. AddBookmark проверяет каталог/ACL и пишет метаданные без вычисления счётчиков. Ошибки авторизации/SQLite/ресурсов/отмена не становятся успешным пустым ответом. MCP и другие существующие потребители не переводятся на новый режим автоматически.

### 2. Раздельное состояние двух списков, общий вид

Переиспользовать ConferenceCard, расширив её управлением видимостью статистики; одинаковые отступы, заголовки групп, bookmark-действия, индикаторы и retry. Избранное — начальная вкладка; вкладка общего каталога явно названа «Все области», чтобы не потерять доступ к личным и служебным областям. История и профиль сохраняются. Поиск общего каталога остаётся в нём; отдельный поиск избранного не добавляется.

Каждая вкладка хранит в памяти сессии запрос, строки, offset/hasMore, прокрутку и состояние ошибки. Загружать первую страницу активной вкладки; остальные — по достижении конца списка с защитой от параллельных запросов. Не догружать полный каталог в фоне. Новая страница дополняет список по ID; отсутствие прогресса — ошибка с повтором, не бесконечный цикл. При смене запроса отменять обход и игнорировать прежние ответы. Ошибка следующей страницы оставляет видимые строки и отдельный retry; hasMore не выдаётся за завершённость.

Пустое избранное показывает «Выбрать эхи», открывающую общий каталог. Переключение вкладок само по себе не запускает сетевое обновление уже загруженного состояния. Ручное обновление и resume запрашивают актуальную первую страницу только активного списка, сохраняя фильтр; прочие страницы инвалидируются. Холодное избранное всегда читается с сервера. Постоянное хранение приватных строк не добавляется; кеш общего каталога разделяется по серверу/профилю/режиму/фильтру/сортировке/размеру страницы и версии схемы.

### 3. Подтверждённые изменения и точечная актуализация

Добавление/удаление использует существующий RPC, pending только у строки. До ответа подтверждённый bookmark-флаг не меняется. После успеха обновляется запись по ID в обоих состояниях и инвалидируется только состав избранного/снимок навигации. Общий каталог не перечитывается и не теряет прокрутку. Если вставка в незагруженную страницу избранного не может быть корректно размещена, пометить его страницы устаревшими и обновить первую при следующем открытии; это не обновляет общий каталог. При изменении состава избранного сбросить старые offsets, не добавлять к ним страницы нового состава.

MessageScreen возвращает набор затронутых ID (чтение, MarkUnread, массовая отметка, отправка, межэховый переход). Для загруженных избранных строк запрашивать GetConference только по этим ID, дедуплицируя запросы. Числа не вычислять локальным вычитанием: сервер остаётся источником истины. Общему каталогу статистика не нужна. История помечается устаревшей после подтверждённого чтения и обновляется при открытии. Точечный сбой не отменяет успешную мутацию и не вызывает перечитывание всех эх; показать отдельный повтор.

При отзыве доступа удалять затронутые данные по прежним правилам; при смене сервера/профиля/токена отменять запросы, очищать списки, pending и навигационный снимок. Не использовать приватный кеш при сетевой ошибке вместо текущей проверки прав.

### 4. Ленивый снимок избранного для навигации

Открытие письма не ждёт догрузки общего списка или всех статистик избранного. При первом межэховом «Следующее» получить полный список метаданных избранного (bookmarked_only=true, omit_statistics=true), отменяемо и с контролем прогресса. На время этого действия показать pending, текущее письмо остаётся доступным. Снимок фиксируется для оставшейся жизни данного reader; поздние серверные изменения учитываются новым чтением/обновлением, ACL кандидата всегда проверяется заново. В совместимом пути использовать полный ListBookmarks без общего каталога.

Кандидаты — только читаемые поддерживаемые EchoArea. Сортировка по отображаемому имени без учёта регистра и ID. Если текущая эха входит в снимок, обходить после неё с одним переходом через конец; если не входит — с первой избранной. Каждый ID проверяется один раз за действие; пустой снимок останавливает межэховый переход. Исходный поиск полного списка и порядок истории больше не ограничивают кандидатов — это намеренная замена прежнего требования.

Сохранить существующую проверку актуальной прочитанности кандидата, правила персональных фильтров, отсутствие отметки пропущенных писем прочитанными, различение ошибки и отсутствия непрочитанных. «Предыдущее», цепочки, личные и служебные области сохраняют текущие границы.

### 5. Удаление Intel из всех связанных перечней выпуска

Убрать обе строки Intel в build.yml и runner из прогрева. Состав settings.json уменьшить с восьми до шести пакетов, синхронизировать генерацию/проверки manifest, метрик, feeds, документацию и тесты, если они предполагают восемь. Контейнер linux/amd64 сохраняется. Проверки остальных платформ и запрет публикации неполного набора сохраняются.

Существующие валидаторы исторических подписанных пакетов должны продолжать распознавать macOS x86_64: не удалять архитектуру из общего чтения старых манифестов. Новые релизы не предлагают ARM-пакет Intel-установке. Старые tags/assets/feeds не переписывать. Расщепить составной шаг pub get + test на именованные шаги для честной диагностики времени, без уменьшения тестового покрытия.

## Risks / Trade-offs

- [Общий список больше не выделяет непрочитанные] → согласовано; точные значения доступны в избранном, режим явно различается.
- [Очень много избранного] → статистика только страницы; начальное открытие письма не ждёт полного списка; снимок переходов без JAM.
- [Большая одиночная эха всё ещё медленно считает статистику] → сохраняем точность, измеряем задержку отдельно; индекс/агрегация — отдельное изменение при необходимости.
- [Поступления и действия другого устройства] → точечная актуализация, ручное обновление и resume; мгновенная синхронизация всех вкладок не обещается.
- [Изменение состава во время offset-пагинации] → после локальной мутации сброс offsets избранного; дедупликация, явное обновление при внешних изменениях. Снимковая серверная пагинация не вводится.
- [Откат сервера] → capability определяется заново при восстановлении сессии, прежний API остаётся доступен; не смешивать кеши режимов.
- [Intel перестаёт получать новые пакеты] → явно документировать, сохранять исторические файлы и совместимость их чтения. Общая длительность релиза всё ещё может зависеть от ARM/очереди runner.

## Migration Plan

1. В apply реализовать additive контракт и backend, обновить generated bindings и проверки совместимости.
2. Реализовать состояние UI/навигацию и регрессии, затем согласованно изменить матрицу/перечень пакетов/документацию.
3. Проверить root CMake/CTest с реальным тестовым HPT, Flutter analyze/test, generated bindings, release-tools и CI оставшихся платформ. Не трогать активные старые OpenSpec changes.
4. До будущего выпуска обновлять сервер раньше клиента для быстрого режима; откат не требует изменения SQLite/JAM. Публикация и обновление amster2 требуют отдельного запроса.
5. В приёмочном отчёте сравнить исходный и новый пути на одной синтетической базе: 514 областей, несколько размеров избранного, холодный/тёплый запуск, первая страница/поиск/мутация/возврат. Зафиксировать RPC, открытия JAM, чтения заголовков и длительности; не обещать коэффициент ускорения до измерений. Проверяемые инварианты: 0 JAM при лёгком каталоге, статистика не более размера страницы, 0 перечитываний каталога при мутации/возврате/простом переключении вкладок.
