# Spec Delta

## MODIFIED Requirements

### Requirement: Один локальный шаблон
Клиент SHALL предоставлять в настройках один общий многострочный шаблон для новых писем, ответов и пересылок во всех областях. Сохранение SHALL быть независимым от подключения к серверу, сохранять текст между запусками и не изменять Tagline/Origin. При отсутствии настройки и после сброса SHALL использоваться встроенный шаблон GoldED; синхронизация между устройствами не выполняется.

#### Scenario: Перенос текста
- **WHEN** пользователь вставляет текст `.tpl`, сохраняет и перезапускает клиент
- **THEN** текст доступен без изменения синтаксиса, а новые редакторы используют сохранённый шаблон
- **AND** настройки сервера, профиля, Tagline и Origin не меняются

#### Scenario: Отсутствие настройки и сброс
- **WHEN** пользователь не настраивал шаблон либо сбросил его
- **THEN** настройки показывают встроенный шаблон, а новые письма, ответы и пересылки используют его
- **AND** явно сохранённый пустой шаблон отличается от отсутствующей настройки и создаёт пустое тело

#### Scenario: Обновление приложения
- **WHEN** приложение обновляется и существует сохранённый пользовательский шаблон, включая пустой
- **THEN** его текст не изменяется и продолжает применяться
- **AND** при отсутствии сохранённой настройки новое оформление применяется без ручного переноса

## ADDED Requirements

### Requirement: Содержание встроенного шаблона
Встроенный шаблон SHALL соответствовать адаптированному английскому шаблону GoldED ниже. Комментарии не влияют на результат; значимые строки, пустые строки и порядок SHALL сохраняться. Настройки, создание черновика и действие «Вставить пример» SHALL использовать один и тот же текст.

#### Scenario: Канонический текст
- **WHEN** пользователь открывает настройки без сохранённого шаблона либо сбрасывает его
- **THEN** доступен следующий текст:

```text
; Оформление пересылки
@Forward=============================================================================
@Forward* Forwarded by @CName (@CAddr)
@Forward* Area : @OEcho (@ODesc)
@Forward* From : @OName, @OAddr (@ODate @OTime)
@Forward* To   : @DName
@Forward* Subj : @Subject
@Forward=============================================================================
@Message
@Forward=============================================================================
@Forward

; Приветствие
Hello, @pseudo!
@New
@Position

; Ответ без цитаты
@ReplyReply to message from <@ODate>, @OName -> @DName:

; Ответ с цитатой
@Quoted@ODate @OTime, from @OName -> @DName:
@Quote

Best Regards, @CFName
```

#### Scenario: Новое письмо и позиция курсора
- **WHEN** создаётся новое письмо без пользовательского шаблона
- **THEN** тело содержит приветствие и подпись с подстановкой имени получателя и первого имени отправителя
- **AND** курсор находится на месте `@Position`, а строки ответа, шапка пересылки и исходный текст отсутствуют
- **AND** для получателя `All` сохраняется существующая семантика `@pseudo`: приветствие имеет вид `Hello, !`

#### Scenario: Ответы
- **WHEN** создаётся ответ без пользовательского шаблона
- **THEN** ответ без цитаты содержит строку `Reply to message from…` без цитаты
- **AND** ответ с цитатой содержит строку даты и участников переписки и ровно одну FTN-цитату
- **AND** оба варианта содержат приветствие и подпись, курсор располагается перед строкой ответа

#### Scenario: Пересылка
- **WHEN** создаётся пересылка без пользовательского шаблона
- **THEN** шапка пересылки с данными исходного письма и его тело вставляются один раз перед приветствием и подписью
- **AND** прежняя штатная шапка не добавляется повторно

#### Scenario: Пример и предпросмотр
- **WHEN** пользователь нажимает «Вставить пример»
- **THEN** в редактируемое поле вставляется встроенный шаблон без автоматического сохранения
- **AND** предпросмотр использует этот текст и показывает тело и курсор для всех четырёх действий без ошибок совместимости
