# Design

## Context

См. мотивацию в proposal.md. `TemplateSettings.read()` сейчас возвращает null при отсутствии ключа, что оставляет прежнее оформление в `message_screen.dart`. Панель самостоятельно читает сохранённый текст, первоначально показывает пустое поле, а после сброса очищает его. Короткий `templateExample` существует только в панели. Формат хранения версии 1 уже различает отсутствующий ключ и сохранённую пустую строку.

## Goals / Non-Goals

**Goals:** обеспечить одинаковый встроенный текст в настройках, предпросмотре, примере и новых черновиках; сохранить приоритет пользовательских данных и однократное применение.

**Non-Goals:** изменение движка GoldED, перевод шаблона на русский, исправление его литературного оформления, новые переключатели оформления, файловый импорт, изменение сервера или выпуск релиза в рамках этого изменения.

## Decisions

1. Разместить канонический текст в общей константе в модуле шаблонов, доступной настройкам и панели. Использовать существующий движок. Альтернатива — отдельные реализации стандартного оформления — создаёт риск расхождения результатов.
2. При отсутствии ключа `TemplateSettings.read()` возвращает встроенный `TemplateBundle`. Не сохранять его автоматически: отсутствие ключа означает использование актуального встроенного текста, а наличие ключа всегда означает пользовательское переопределение. Версия JSON и ключ не меняются. Альтернатива — миграция с записью значения на диск — лишает различия между встроенным и пользовательским текстом.
3. Панель загружает эффективный текст через общую логику настроек, после успешного сброса отображает встроенный текст и обновляет снимок сохранённого состояния. «Вставить пример» подставляет ту же константу, сохраняя обычное явное сохранение. Ошибка сброса не должна показывать ложный успех или стирать введённый текст.
4. Сохранить явную обработку повреждённой настройки. Не заменять её незаметно встроенным шаблоном. Кнопка «Использовать штатное оформление» при ошибке по-прежнему выбирает существующее аварийное оформление для текущего черновика, без изменения настройки. Это отдельный путь, не действие сброса.
5. Текст берётся буквально из согласованного блока: английские фразы, `@pseudo`, один `@Position`, переносы и порядок блоков. Удалять пустые строки и менять приветствие на `@TName` не требуется. Альтернатива с улучшением приветствия изменила бы выбранный пользователем шаблон.

## Risks / Trade-offs

- [Установки без настройки получают новое оформление после обновления] → явно закрепить поведение в спецификации; пользователь может сохранить пустой или собственный шаблон.
- [Для All получается `Hello, !`, а пустые строки остаются и при неактивных условных блоках] → сохранить выбранный текст, проверить точный результат и возможность его редактирования; не менять семантику движка ради оформления.
- [Получение профиля теперь требуется и при отсутствии настройки] → проверить создание черновика и существующую обработку ошибок, обновить фикстуры тестов осмысленным профилем.
- [Дублирование шапки пересылки или цитаты] → проверить результат создания черновика, а не только рендеринг константы.

## Migration Plan

Миграция данных не требуется: после обновления отсутствие ключа разрешается во встроенный текст, существующие значения сохраняют приоритет. HTTP API и совместимость с текущим сервером не меняются. Откат клиента возвращает прежнее оформление для отсутствующего ключа; пользовательские значения остаются читаемыми.
