# Design

## Context

Мотивация приведена в proposal.md. В apps/frontend/lib/pages/message_screen.dart navigateUnread каждый раз начинает поиск страниц текущей эхи с offset 0, затем увеличивает orderIndex только до конца conferenceOrder. hasNextEcho также видит только хвост списка. После getMailboxState следующего кандидата статистика не учитывается: даже известный ноль вызывает постраничное чтение. На сервере проверены только списки и счётчики, без GetMessage и изменения прочитанности; это подтверждает наличие непрочитанных раньше текущей эхи, но не восстанавливает точный снимок порядка на устройстве пользователя.

Исходный порядок уже передают reader_app.dart и personal_conferences.dart; главный каталог группирует непрочитанные эхи перед прочитанными, персональные списки имеют собственный порядок. MessageRepository предоставляет GetConference, ListMessages и защиту epoch/cancellation. Widget-тесты unread_echo_navigation_test.dart покрывают линейный переход, ошибки, закрытие и смену сессии; проверки кругового перехода и отсутствия ListMessages при свежем нуле отсутствуют.

В основной message-access пока нет требования межэхового перехода. Оно добавлено завершённым, но не архивированным unread-echo-navigation-and-app-icon с прямым запретом кругового обхода. Поэтому delta этого изменения содержит полный обновлённый блок последовательного чтения и ADDED блок продолжения, отсутствующий в основной спецификации. При будущей синхронизации использовать новое правило как замену одноимённого старого; не восстанавливать запрет кругового обхода при позднем архивировании старого изменения. Сейчас основные спецификации и старое изменение не редактируются.

## Goals / Non-Goals

**Goals:** ограниченный круговой поиск других эх с минимальным числом запросов страниц, сохранением текущего письма до успешного открытия и существующих гарантий отмены.

**Non-Goals:** серверный unread-фильтр, миграции, смена порядка сообщений, круговой поиск внутри текущей эхи, переход назад между эхами, новые зависимости и параллельный обход всего каталога. Оптимизация повторного сканирования страниц текущей эхи отдельно не входит: после её исчерпания исправляется именно межэховый поиск.

## Decisions

### Один круг по неизменяемому списку

Для каждого действия вперёд после исчерпания текущей эхи сформировать последовательность: хвост после текущего индекса, затем начало до него. Исключить текущий ID, дубли ID, другие типы, заведомо недоступные и неподдерживаемые области. Каждый кандидат посещается не более раза за действие; успешное открытие завершает действие и становится новой точкой отсчёта следующего нажатия. При отсутствии текущей эхи в контексте межэховый переход не выполняется. hasNextEcho должен пользоваться теми же правилами кандидатов, а не отдельной проверкой хвоста.

Это сохраняет контекст источника. Повторная загрузка всего каталога вместо исходного списка отвергнута: она нарушает фильтр и порядок закладок/истории. Бесконечное увеличение индекса по модулю без множества посещённых отвергнуто из-за риска повторов.

### Свежие счётчики перед страницами

Для каждого кандидата вызвать существующий getMailboxState. Проверить ID, тип, доступ и формат. Если statisticsKnown и unreadCount == 0, сразу перейти к следующему кандидату. Старый ноль из conferenceOrder не является основанием для пропуска серверной проверки. При неизвестной статистике либо положительном счётчике сканировать страницы до первого непрочитанного с учётом opened; GetMessage вызывать только для выбранной цели. При положительном счётчике без непрочитанных строк продолжить круг.

Не применять нулевой счётчик как замену проверки выбранного сообщения/поколения текущей эхи: сохраняется её существующий механизм поиска. Нет длительного кеша нулей: новое действие проверяет кандидатов снова. Последовательный обход выбран вместо параллельного для сохранения порядка и управляемой нагрузки. Производительность проверяется количеством RPC, а не нестабильным временем wall-clock.

### Завершение, повтор и жизненный цикл

Только исчерпание полного круга устанавливает echoesExhausted. При этом загрузка прекращается, текущее письмо остаётся и показано существующее сообщение об отсутствии дальнейших непрочитанных. Обновление/повторный вход сбрасывает исчерпание. Если доступных кандидатов нет, кнопка не предлагает бессмысленный переход. «Предыдущее», цепочки, личные и служебные области сохраняют прежнюю семантику.

На всех await сохраняются version, epoch и cancellation. Двойное нажатие блокируется loading. Сетевая ошибка оставляет текущее письмо, показывает повтор и не устанавливает исчерпание; повтор начинает новое ограниченное действие от текущей эхи. NOT_FOUND/PERMISSION_DENIED у других эх пропускаются по действующим правилам. Смена поколения по-прежнему требует явного обновления.

## Risks / Trade-offs

- [Письмо поступило после свежего нуля или в уже проверенную эху] → поиск не является атомарным снимком; обновление начинает новый обход, постоянного отрицательного кеша нет.
- [Неизвестная статистика и много прочитанных страниц] → постраничный поиск остаётся необходимым с текущим API; отмена и индикатор сохраняются, обещания постоянного времени нет.
- [Одна эха, повтор ID или все эхи прочитаны] → уникальные кандидаты и исключение текущего ID гарантируют конечность; тесты проверяют число запросов и снятие loading.
- [Чтение другим устройством между ListMessages и GetMessage] → сохраняется существующая неатомарность выбора; API и read-state не меняются этим исправлением.
- [Поздняя синхронизация старого изменения] → при синхронизации/архивировании сверить одноимённое требование и сохранить новое круговое поведение, не переписывая исторические архивы.

## Migration Plan

После apply и клиентских проверок изменение поставляется обычным обновлением клиента, совместимым с установленным backend. Данные не мигрируют, сервер не требует обновления. Откат клиента возвращает линейный поиск; уже прочитанные письма сохраняют серверные отметки. Выпуск, публикация, архивирование и развёртывание выполняются отдельными запросами.
