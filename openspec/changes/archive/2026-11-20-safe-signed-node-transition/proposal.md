# Proposal

## Why

Приёмка Mini App на основном backend завершена, но штатные автообновления amster2
остаются на паузе. Аудит 19.11.2026 выявил несовместимый stable v1.0.27 (schema ≤11
при рабочей 12), неподдерживаемую identity локального кандидата, обновление только
одного сервиса вместо пары и устаревший состав maintenance backup. Прямое снятие
паузы не обеспечивает сохранение Telegram-привязок, персональных ящиков и gateway.

## What Changes

- Явный переход с точно идентифицированной локальной пары на выбранный подписанный
  релиз без подделки BUILD.json и без ослабления обычной проверки identity/sequence.
- Согласованная транзакция backend/tosser: подготовка обоих образов до остановки,
  сохранение исходных pins, журналируемое переключение, проверки и безопасный откат
  обоих сервисов, включая локальные image ID без RepoDigest.
- Полный stopped-node backup и восстановление: данные FTN, schema 12, Telegram и
  сеансы, персональные ящики, updater, gateway/TLS/ACME/cron/firewall и инструменты.
- Блокирующие проверки места, совместимости, восстановления и защиты новых записей;
  репетиция с отказами и перезапуском управляющего процесса только на копиях.
- Сохранение существующего single-service updater; парный режим подключается явно.
  Актуализация устаревших schema-сценариев server-updates на 9–12.

Этот change готовит код, тесты и процедуру. Выпуск подписанного production-релиза,
работы на amster2, очистка диска, применение перехода, firewall/Pages и возобновление
автообновлений не входят в реализацию без отдельного поручения. Отправка в FidoNet
не нужна ни для одной приёмочной проверки.

## Capabilities

### New Capabilities

Нет: используются существующие границы возможностей.

### Modified Capabilities

- `server-updates`: локальное происхождение и signed sequence, парные Compose
  update/rollback, проверки сохранности и совместимости schema 12.
- `node-backup`: полный deployment-комплект с отдельным gateway, интеграция в
  maintenance-транзакцию и репетиция актуального состояния.

## Impact

Затронуты scripts/update/common.py, discovery.py, ffido-docker-update.py и их тесты;
scripts/node_backup.py и scripts/test_node_backup.py; безопасная версионируемая
подготовка host maintenance-инструментов из docs/deployment/amster2-miniapp
(на сервере сейчас находится ffido/ops/manage.py); Compose rehearsal и документация.
Для release gate используются scripts/release/update_metadata.py и существующий
schema compatibility gate. По подтверждённому расширению добавляется передача
maintenance lease в C++ CLI ffido-admin mailbox-restore и её регрессионные тесты.
Публичные gRPC/Dart API и protobuf не меняются: проверяется
сохранение уже реализованных Telegram/mailbox контрактов.

Новых библиотек, ключей доверия или постоянно работающих служб не требуется.
Старые подписанные manifests и архивы не переписываются. Существующие dirty-изменения
монорепозитория не считаются автоматически включёнными в будущий релиз.
