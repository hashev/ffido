# Spec Delta

## ADDED Requirements

### Requirement: Отмена при медленном потребителе результатов
Если потребитель временно не читает stdout, MCP SHALL продолжать принимать уведомления отмены уже активных вызовов и передавать отмену их RPC. Ожидание вывода SHALL не удерживать блокировку учёта активных вызовов. Память ожидающих ответов SHALL иметь конечный бюджет; при его исчерпании процесс SHALL управляемо завершать соединение без потери подтверждённых публикаций и без ложного успеха.

#### Scenario: Заполненный выходной канал
- **WHEN** потребитель перестал читать stdout и отправил отмену другого активного инструмента
- **THEN** отмена достигает его RPC до освобождения stdout, а расход памяти остаётся в заданном бюджете

#### Scenario: Возобновление чтения
- **WHEN** потребитель возобновил чтение до исчерпания бюджета ожидающих ответов
- **THEN** сервер передаёт целые JSON-RPC сообщения с правильными ID и продолжает обслуживать ping и инструменты

#### Scenario: Переполнение бюджета ответов
- **WHEN** потребитель продолжает посылать запросы без чтения ответов и бюджет ожидающего вывода исчерпан
- **THEN** сервер завершает соединение с локальной диагностикой без секретов, отменяет незавершённые RPC и не сообщает об успешной публикации без подтверждения backend
