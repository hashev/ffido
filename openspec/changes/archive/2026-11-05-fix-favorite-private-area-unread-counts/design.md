# Design

## Context

В `apps/frontend/lib/conference_card.dart` индикатор внутри trailing Row дополнительно ограничен `conference.kind == AreaKind.echo`. Это непосредственно скрывает счётчики остальных типов. `PersonalConferences` передаёт в карточку `unreadCount`, `statisticsKnown`, тип и права; в избранном включает `showStatistics` и `showZeroCount`, а в каталоге выключает статистику.

`ConferenceService::Describe` в `apps/backend/src/service/conference_service.cpp` считает непрочитанные по персональным отметкам для любой читаемой поддерживаемой JAM, независимо от типа; personal_mailbox дополнительно обрабатывает позицию чтения. На клиенте `PersonalConferences.open` собирает затронутые ID, а `changed` обновляет загруженную карточку через GetConference. Эти пути не ограничены эхами. Причина установлена по исходникам; живые ответы amster2 в рамках планирования не запрашивались.

Существующие тесты карточки в основном проверяют EchoArea. В `personal_screens_test.dart` есть строка Netmail, но отсутствует самостоятельная проверка её положительного счётчика. Нужны регрессии конкретно для Netmail/LocalArea и возврата из чтения.

## Goals / Non-Goals

**Goals:** восстановить отображение уже доступных серверных значений для двух затронутых типов; зафиксировать отличие нуля от неизвестной статистики и точечное обновление без лишних RPC.

**Non-Goals:** изменение алгоритма подсчёта, выделение только входящей почты, новые виды статистики, раскрытие служебных счётчиков, изменение ACL, обновление протокола и переработка кеша.

## Decisions

### 1. Уточнить условие отображения в общем виджете

Сохранить существующий путь EchoArea и разрешить тот же индикатор для читаемых NetmailArea и LocalArea. Для новых типов использовать действующие права чтения; не вводить совпадения с текстами Netmail/personal.mail и не требовать personalMailbox=true. Таким образом исправляются и сырые области владельца, и персональные netmail-ящики поинтов, и другие локальные области.

Переиспользовать текущие цвет, форму, padding, доступное название и условия showStatistics/showZeroCount/statisticsKnown. В избранном ноль остаётся видимым, а неизвестное значение обозначается прочерком. Служебные Bad/Dupe/Robots не включать в расширение. Альтернатива с отдельными карточками создаёт дублирование; полное удаление ограничения по типу необоснованно расширяет изменение на служебные области.

### 2. Сервер остаётся источником статистики

Не подменять unreadCount общим totalCount, количеством строк страницы, JAM-атрибутом Read или количеством только входящих. Полученные API-значения сохраняют прежнюю персональную семантику. Backend и protobuf не меняются; текущая совместимость клиента с прежними серверами сохраняется.

### 3. Переиспользовать актуализацию и лёгкий каталог

Проверить существующий цикл onChanged → notifyRead → changed/GetConference для Netmail и LocalArea. Цель — использовать его без новых загрузок каталогов и без локальной арифметики. Положительный результат должен быть виден после чтения и отметки непрочитанности; ошибка допускает прежний повтор, поздний ответ отбрасывается после смены сессии. Общий каталог продолжает передавать showStatistics=false, поэтому новые индикаторы там не появляются.

### 4. Регрессии в существующих тестах

В `conference_card_test.dart` параметризовать новые типы: положительное число, известный ноль при showZeroCount=true, неизвестная статистика, showStatistics=false, отсутствие права чтения. Проверить отсутствие расширения служебных типов и прежнее поведение эх.

В `personal_screens_test.dart` проверить смешанное избранное с Netmail, LocalArea personal.mail и эхой; отдельно включить personalMailbox=true и другие имена/ID, чтобы исключить специальные случаи. Охватить новый облегчённый API и прежний серверный fallback, не вводя нового кеширования приватных данных.

В `catalog_return_test.dart` проверить уменьшение счётчика до нуля, отметку непрочитанности, ошибку/повтор и поздний ответ после смены сессии. Считать RPC: GetConference относится к затронутой области, полный каталог повторно не запрашивается. Использовать FakeTransport, без чтения или отправки реальной почты.

Проверить 320 dp и широкий экран, обе темы, масштаб текста до 200% с обычными счётчиками, понятные semantics и действие закладки. При необходимости расширить существующий тест визуального оформления; результат внести в `docs/testing.md`.

## Risks / Trade-offs

- [Скрытая раньше статистика неизвестна у повреждённой базы] → показывать прочерк и прежнее объяснение, не вычислять ноль.
- [Фикстуры без canRead проверяют неподходящий сценарий] → явно задавать права и известность статистики; отсутствие права чтения проверять отдельно.
- [Исправление затронет лёгкий общий список или служебные типы] → отдельные отрицательные регрессии для showStatistics=false и Bad/Dupe/Robots.
- [Счётчик устареет после чтения] → проверки существующей цепочки уведомлений, повтора и изоляции сессии с контролем числа RPC.

## Migration Plan

Миграции настроек, БД и серверной конфигурации не нужны. Исправление поставляется обычным обновлением клиента после проверок. Откат клиента возвращает прежнее отображение; серверные отметки прочитанности остаются сохранными.
