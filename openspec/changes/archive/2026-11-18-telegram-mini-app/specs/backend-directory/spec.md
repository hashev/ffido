# Spec Delta

## Purpose

Обеспечивает подключение Web-клиента только к проверенным узлам из публичного каталога с контролируемым обнаружением и переносом серверов.

## ADDED Requirements

### Requirement: Проверенный публичный каталог
Web-клиент SHALL выбирать backend только из проверенного каталога GitHub Pages. Каталог SHALL содержать устойчивый уникальный ID, название, FTN-адрес узла и HTTPS endpoint без секретов. Добавление узлов SHALL проходить проверку через PR; ручной ввод endpoint SHALL отсутствовать в этой Web-сборке.

#### Scenario: Выбор узла
- **WHEN** пользователь выбирает узел или открывает ссылку с его ID
- **THEN** endpoint берётся из каталога; название и домен показаны до ввода HPT-пароля

#### Scenario: Подставной адрес
- **WHEN** ссылка содержит неизвестный ID или произвольный endpoint
- **THEN** клиент не подключается к этому адресу и предлагает выбор из каталога

### Requirement: Ограниченное обнаружение профилей
На новом устройстве клиент SHALL требовать ручной выбор узла и не опрашивать весь каталог Telegram-данными. На знакомом устройстве SHALL проверяться только ранее добавленные узлы, ещё разрешённые каталогом. Недоступность одного узла SHALL не блокировать остальные.

#### Scenario: Новое устройство
- **WHEN** локальный список узлов отсутствует
- **THEN** до явного выбора узла ни одному backend не передаётся Telegram-идентичность

#### Scenario: Знакомое устройство
- **WHEN** пользователь ранее добавлял два узла из десяти и один из двух недоступен
- **THEN** запросы направлены только этим двум; второй доступен, а ошибка первого показана отдельно

### Requirement: Доступность и обновление каталога
Клиент SHALL использовать последнюю успешно загруженную и проверенную копию каталога при сетевой ошибке. Без такой копии первый запуск SHALL показывать ошибку с повтором. Успешное обновление с удалением узла SHALL блокировать последующие подключения к нему.

#### Scenario: Каталог недоступен
- **WHEN** загрузка завершается ошибкой и имеется корректная сохранённая копия
- **THEN** выбор работает по этой копии; ошибка не заменяет каталог пустым списком

#### Scenario: Первый запуск без сети
- **WHEN** каталог недоступен и корректной копии нет
- **THEN** показана ошибка с повтором, произвольные подключения не разрешаются

#### Scenario: Удалённый узел
- **WHEN** успешно обновлённый каталог больше не содержит ранее добавленный узел
- **THEN** клиент блокирует его сетевые операции, не изменяет серверные привязки и сохраняет локальные черновики для копирования текста или удаления

### Requirement: Подтверждённый перенос endpoint
Изменение endpoint при сохранении ID узла SHALL требовать подтверждения с показом старого и нового адресов. До подтверждения новый адрес SHALL не получать Telegram-данные, пароли или сессии. Старая сессия SHALL не передаваться новому endpoint; после согласия требуется новый вход.

#### Scenario: Обновлённый адрес
- **WHEN** каталог меняет endpoint ранее добавленного узла
- **THEN** новые запросы к старому адресу приостанавливаются, новый не получает секреты, пока пользователь не подтвердит перенос

#### Scenario: Подтверждение переноса
- **WHEN** пользователь подтверждает новый адрес
- **THEN** клиент выполняет отдельный вход на нём, не используя старый токен; данные прежнего endpoint не показываются под новой идентичностью до подтверждённого сопоставления

### Requirement: Забыть узел локально
«Забыть узел» SHALL завершать его локальные сеансы, удалять сохранённый выбор, персональный кеш и черновики после предупреждения, а также прекращать автоматические проверки. Серверные Telegram-привязки SHALL сохраняться. Отсутствие сети SHALL не мешать локальному удалению.

#### Scenario: Удаление с устройства
- **WHEN** пользователь подтверждает «Забыть узел» с предупреждением о черновиках
- **THEN** локальные данные удаляются для всех его профилей этого узла, другие узлы не затрагиваются, удалённые сессии отзываются при доступном соединении

#### Scenario: Повторное добавление
- **WHEN** пользователь снова выбирает забытый узел с действующими Telegram-привязками
- **THEN** связанные профили доступны после проверки Telegram без повторного HPT-пароля
