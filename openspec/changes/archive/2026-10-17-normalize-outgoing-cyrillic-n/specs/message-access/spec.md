# Spec Delta

## ADDED Requirements

### Requirement: Замена кириллической Н в исходящих письмах
Сервер MUST заменять каждое вхождение кириллической `Н` (U+041D) на латинскую `H` (U+0048) в тексте, теме, имени автора и имени получателя нового исходящего письма перед сохранением в JAM. Правило MUST действовать для новых писем, ответов и пересылок из любого клиента.

#### Scenario: Все вхождения и остальные символы
- **WHEN** каждое из четырёх полей исходящего письма содержит `НН H н`
- **THEN** сохранённое и прочитанное обратно значение каждого поля содержит `HH H н`, без иных изменений символов

#### Scenario: Цитаты и пересылка
- **WHEN** тело письма содержит кириллическую `Н` в цитатах или включённых заголовках пересылаемого письма
- **THEN** все эти вхождения также заменяются на латинскую `H`

#### Scenario: Доверенные имена
- **WHEN** имя автора взято из профиля, а имя получателя ответа — из исходного письма
- **THEN** оба имени в новом письме проходят ту же замену
- **AND** профиль и исходное письмо остаются без изменений

#### Scenario: Сохранение кодировки
- **WHEN** письмо сохраняется в JAM с настроенной CP866
- **THEN** вместо каждой исходной `Н` записывается ASCII-байт `0x48`, остальные символы кодируются по прежним правилам и CHRS остаётся `CP866 2`

### Requirement: Идемпотентность при замене символов
Нормализация MUST сохранять действующую идентификацию операции по исходному запросу. Повтор завершённой операции MUST возвращать ранее сохранённый результат без повторной записи; изменение исходного запроса с тем же ключом MUST возвращать `ALREADY_EXISTS`, даже если нормализованные значения совпадают.

#### Scenario: Повтор и конфликт
- **WHEN** успешно отправленное письмо с `Н` повторяют с тем же ключом и исходным запросом
- **THEN** сервер возвращает исходный результат без дополнительного сообщения
- **WHEN** в запросе с тем же ключом меняют `Н` на `H`
- **THEN** сервер возвращает `ALREADY_EXISTS`
