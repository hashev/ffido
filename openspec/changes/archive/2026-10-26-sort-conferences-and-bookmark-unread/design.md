# Design

## Context

См. `proposal.md`, раздел Why. `reader_app.dart` запрашивает страницы через `ConferenceRepository`, преобразует их в `FidoConference` и сортирует только накопленные элементы по `kind.groupLabel`/enum и имени. Сервер `ConferenceService::GetConferences` применяет пагинацию до передачи результата клиенту; сортировка `unread` упорядочивает по числу, а не по наличию непрочитанных. Поэтому ни сортировка одной страницы, ни переход на существующий `CONFERENCE_SORT_UNREAD` не выполняют требования.

`Conference` уже содержит `kind`, `unreadCount`, `statisticsKnown`. `AccountRepository.getBookmarks` получает полную `Conference` в каждом элементе. `PersonalConferences` отображает имя и описание, но trailing занят кнопкой удаления. Он общий для закладок и истории, обновляется при активации вкладки и возврате из чтения. `ConferenceCard` скрывает ноль и неизвестную статистику; изменение его оформления не требуется.

## Goals / Non-Goals

**Goals:** единый детерминированный порядок полного результата главного списка и доступный счётчик в закладках с сохранением текущих гарантий поиска, отмены, доступа и прочитанности.

**Non-Goals:** сортировка закладок и истории, изменение порядка писем и выбора адресата пересылки, серверных правил прочитанности, ролей и FTN-конфигурации; расширение API и обновление зависимостей.

## Decisions

1. **Собирать полный каталог на клиенте перед публикацией отсортированного результата.** Добавить специализированную операцию полной загрузки в `ConferenceRepository`, сохранив существующие постраничные методы для других потребителей. Последовательно получать страницы существующего ListConferences с прежним поисковым запросом и сортировкой NAME, соблюдать cancellation/epoch между запросами. Offset увеличивать по числу полученных элементов; завершать по has_more, обнаруживать пустую страницу при has_more и отсутствие прогресса. ID дедуплицировать; не использовать число видимых отсортированных элементов как серверный offset. Главный экран публикует результат атомарно по своему requestVersion и больше не предлагает «Загрузить ещё» для каталога. Это даёт правильное положение даже области с последней страницы. Альтернатива — новый серверный sort enum — потребовала бы изменения обеих сторон и согласованного развёртывания для задачи клиента.

2. **Не собирать полный каталог из смеси кешированной первой страницы и свежих остальных.** Полная операция использует сетевые постраничные запросы, не записывает объединённый каталог в кеш первой страницы и не меняет публичную семантику существующих fetch/search. При разрешённой транспортной ошибке допускается только прежний совместимый fallback первой страницы с сохранённым hasMore и явным указанием неполноты; он не считается полным каталогом. При ошибке поздней страницы можно сохранить прежний полностью загруженный список с ошибкой и повтором; новый частичный список не публикуется. Приватные данные по-прежнему не сохраняются в offline-кеше. Тесты фиксируют отсутствие подмены полного результата частичным. Альтернатива — новый полный кеш — добавляет ненужную схему и риски хранения приватных областей.

3. **Явный приоритет типов вместо порядка enum и названий разделов.** Netmail=0, Local=1, Bad=2, Dupe=3, Robots=4, Echo с statisticsKnown && unreadCount > 0 =5, остальные Echo=6. Это сохраняет все поддержанные типы; размещение Robots после Dupe принято как дополнение к перечисленным пользователем типам. Внутри группы сравнивать `name.toLowerCase()`, затем ID. Алфавит определяется отображаемым именем, без локалезависимой колляции. Секции личных/служебных областей сохраняют существующие подписи; при двух группах Echo не требуется повторять одинаковый заголовок «Эхи». Сортировка выполняется после завершения каждого актуального обновления, включая возврат и массовую отметку. Альтернатива — сравнение количества — нарушает алфавит внутри непрочитанных.

4. **Счётчик закладок из уже полученной модели.** В ветке закладок `PersonalConferences` разместить компактный числовой индикатор рядом с кнопкой удаления (Row с mainAxisSize.min), дать доступную подпись «Непрочитанных: N». Показывать 0 при известном нуле, при неизвестной статистике — «—» с пояснением. Применить к EchoArea; другие типы и ветка истории остаются без нового индикатора. Дополнительные RPC на каждую закладку не нужны. Сохраняются обработчики refresh/open/remove и защита версии/сессии.

## Risks / Trade-offs

- [Рост времени первоначальной загрузки] → страницы запрашиваются последовательно с существующим допустимым limit, виден индикатор загрузки; отмена работает на всём обходе. Сравнить число запросов с ожидаемым количеством страниц в тесте. Потоковую сортировку не выдавать за глобальную.
- [Каталог меняется между страницами] → существующий API не предоставляет snapshot; гарантируется порядок полученного набора, дедупликация ID и завершение при отсутствии прогресса. Согласованный снимок при параллельном изменении сервера не добавляется в этой задаче.
- [Старый ответ или кеш меняет состояние] → существующие epoch/requestVersion и правила fallback покрыть тестами для многостраничной операции.
- [Длинное имя и большой счётчик] → проверить узкую ширину, отсутствие overflow, доступность кнопки удаления и semantics.

## Migration Plan

Миграции API, базы и настроек не нужны. Выпустить обновлённый клиент с прежним сервером. Откат — предыдущая версия клиента; серверная прочитанность и закладки сохраняются.
