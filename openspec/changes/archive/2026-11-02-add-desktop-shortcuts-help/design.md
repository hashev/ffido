# Design

## Context

Мотивация и объём описаны в proposal.md. В `apps/frontend/lib/pages/message_screen.dart` уже есть `CallbackShortcuts` с Ctrl+F/F6 и `Focus(autofocus: true)`. Действия реализованы через `compose`, `showSearch`, `navigate`, `canNavigate`; режим `unreadNavigation` отделяет обычную эху от цепочек и остальных областей. Кнопка «К списку» снимает выбранное письмо, а для personalMailbox вызывает загрузку с сохранением цепочки.

`reader_app.dart` содержит MainScreen с общим заголовком каталога и вкладками. Редактор находится в отдельном маршруте того же файла message_screen.dart; доступны вложенные выборы назначения, подтверждения, поиск и просмотр изображений. Единой справки и реестра команд нет. Нельзя подвесить неограниченные обработчики ко всему приложению: фоновый читатель остаётся в дереве, пока пользователь вводит текст.

Существующая спецификация `message-search` требует Ctrl+F/F6; её поведение сохраняется. Текущие незакоммиченные изменения межобластных ответов учитываются как исходное состояние и не переписываются. Новый контракт принадлежит `keyboard-shortcuts`.

## Goals / Non-Goals

**Goals:** один источник сочетаний/подписей и общие обработчики для кнопки и клавиши; контекстная доступность; справка без запроса к серверу.

**Non-Goals:** системные глобальные перехватчики, настройки сочетаний, новый алгоритм непрочитанных вне эх, команды отправки/удаления и новое поведение браузера.

## Decisions

### Реестр команд и границы платформ

Добавить небольшой общий модуль под `apps/frontend/lib/` с идентификатором команды, сочетаниями, подписью и описанием контекста. Из него получать отображаемые клавиши, подсказки и содержимое справки. Состояние доступности и callbacks передаются активным экраном, не хранятся глобально. Реестр не знает репозитории и не отправляет RPC.

Основной модификатор — Ctrl на Windows/Linux и Meta (Cmd) на macOS: U — unread, R — reply, N — new, F — find, L — list. F1 — help, F6 и Ctrl+F остаются совместимыми вариантами поиска. Новые команды включаются только при !kIsWeb и desktop targetPlatform; прежний Ctrl+F/F6 не удаляется в других окружениях. Вместо новых пакетов использовать Flutter Focus/Actions/Shortcuts либо локальную обработку событий внутри области фокуса.

Для пяти букв распознавать физическую позицию латинской клавиши совместно с точными модификаторами; это обеспечивает русскую раскладку. Не реагировать на дополнительные Shift/Alt или чужой основной модификатор; Ctrl+F на macOS — явный отдельный alias. Игнорировать KeyRepeatEvent, а не запускать новый async вызов при каждом повторе. Альтернатива с одними logicalKey проще, но может терять команды при русской раскладке.

### Одна доступность для кнопок и клавиш

В читателе сформировать минимальные predicates/обработчики доступных команд и использовать их для UI и клавиатуры. Права, неподдерживаемая база и текущие loading/bulkBusy/unreadBusy/searchBusy проверяются до запуска; повтор открытия маршрута защищён до завершения открытия/закрытия. Не дублировать алгоритмы в новом модуле.

Следующее непрочитанное: `unreadNavigation && canNavigate(1)` и прежний `navigate(1)`. Не вызывать обычный navigate в Netmail/цепочке с другой семантикой. Команды не открывают письмо из каталога областей — сначала нужно выбрать область.

Ответ: `compose(reply: true)` с обычной цитатой, без crossAreaReply/forward. Новое: `compose()`. Поиск: существующий showSearch, без второй реализации фильтра. Возврат: выделить обработчик нынешней кнопки «К списку», включая personalMailbox; не использовать Navigator.pop и не создавать общий Back shortcut для редактора.

### Фокус и маршруты

Перед выполнением команды читателя проверить, что его ModalRoute текущий и фокус не принадлежит EditableText, в том числе дочернему полю/IME. Это необходимо дополнительно к Focus scope: нажатие может всплыть от поля либо вложенного маршрута. Не вызывать действие во время открытия диалога или уже выполняемой команды.

В редакторе активна только справка из нового набора; Cmd/Ctrl+N/R/U/L/F не управляют нижележащим читателем. Не добавлять команду отправки и не менять PopScope/подтверждение закрытия. Нативные текстовые сочетания и Escape существующих диалогов не перекрываются. Потеря сессии/закрытие экрана сохраняют существующую отмену и epoch-защиту.

### Локальная справка

Общий адаптивный диалог/экран справки доступен через F1 и кнопку с tooltip/semantic label «Горячие клавиши» в MainScreen, MessageScreen и редакторе. Не добавлять пункт меню macOS/Windows в этой версии: экранная кнопка доступна везде и не требует platform channels.

Справка показывает весь фиксированный набор, где он действует, текущую доступность и короткую причину (нет письма, нет права записи, не обычная эха, операция выполняется, не читатель). В каталоге и редакторе действия чтения обозначены как доступные в читателе. Сочетания отображаются из того же реестра, что обработчик. F1 из поля разрешён; закрытие возвращает предыдущий focus node и позицию курсора без перегенерации шаблона. Диалог прокручивается, поддерживает Escape/кнопку закрытия и не открывается несколько раз поверх себя.

## Risks / Trade-offs

- Команда всплывает из редактора/диалога → проверка активного маршрута, EditableText и тесты каждого вложенного экрана.
- Клавиатура и кнопка расходятся в доступности → общие predicates/callbacks, проверки read-only, загрузки и неизвестного формата.
- F1 может требовать Fn на macOS → видимая кнопка и правильная подпись; проверка на реальной платформе при наличии среды.
- Логические символы зависят от раскладки → физическая позиция для букв, unit/widget-тесты латиницы и кириллицы.
- Системное или оконное ПО может перехватить сочетание до Flutter → фиксировать ограничения ручной платформенной проверки; не обходить ОС глобальными hooks.

## Migration Plan

Достаточно обновить клиент; сервер, протокол, bindings и данные не меняются. Нет новых настроек, зависимостей или миграции. Откат клиента возвращает прежний набор команд, не меняя сохранённые письма/сессии. Автоматические проверки охватывают три desktop платформы через platform overrides; реальную доставку событий ОС проверить там, где доступны соответствующие рабочие станции, ограничения записать в docs/testing.md.
