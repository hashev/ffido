# Design

## Context

Причина и замер приведены в `proposal.md`. `CallContext` создаётся в `Serve` один раз на инструмент с deadline `now + 5s`. `Next` передаёт этот абсолютный момент каждому RPC. `ffido_list_areas` сначала получает статистику всех точных разрешённых ID, затем применяет query/pagination; этот порядок сохраняет точные total и актуальные серверные права. Клиентские настройки Codex/OpenCode уже допускают 60 секунд.

## Goals / Non-Goals

**Goals:** каталог 514 областей завершает проверенный 13-секундный проход; общий конечный бюджет, отмена и проверка прав сохраняются.

**Non-Goals:** изменение protobuf/API, глобальное увеличение timeout, кеш статистики, пакетный endpoint, сокращение allowlist или изменение `nofile`.

## Decisions

1. Перед запуском worker назначать `ffido_list_areas` deadline `start + 30s`; оставить текущий default 5s для остальных инструментов. Политика выбирается по точному имени инструмента. Не продлевать deadline внутри `Next`: иначе число областей сделает время исполнения неограниченным.
2. Сохранить существующее получение каждой разрешённой области и формат результата. Изменение порядка pagination без полного прохода нарушило бы точность total и query по описанию; новые bulk RPC и кеши расширяют контракт и требуют отдельного проектирования. Здесь достаточно измеренного бюджета с запасом около 2,3 раза.
3. Регрессию проверять через настоящий stdio-процесс MCP и управляемый TLS backend: ответ каталога задерживается более пяти секунд, но укладывается в 30. Backend фиксирует, что последующие RPC получают оставшийся бюджет, а не новые 30 секунд. Отдельно проверить отмену во время задержки и сохранение короткого бюджета обычного инструмента. Использовать существующий `test::McpProcess`, не повышать глобальные ожидания тестов без необходимости.

## Risks / Trade-offs

- Слот каталога может занимать до 30 секунд → максимум четыре активных вызова сохраняется, клиент может немедленно отменить запрос, EOF отменяет активную работу.
- Сильно выросший архив может превысить и 30 секунд → остаётся явная ошибка deadline; это не обещание неограниченного обхода. Пакетный каталог без статистики можно обсуждать отдельно при новом замере.
- Увеличение всех бюджетов затронуло бы поиск и публикацию → исключение применяется только к `ffido_list_areas`; login, отправка, поиск и cleanup сохраняют прежние ограничения.

Обновить amster2 штатным подписанным updater с резервной копией, сохранив действующие MCP-сессии, allowlist и клиентские конфиги. Проверить каталог всех 514 областей через обе SSH-обёртки, остальные инструменты и `idle_jam_fds=0` при `nofile=1024`. Релиз 1.0.20 и его публичные assets/тег не заменять.
