# Персональная почта поинтов без HPT на устройствах

Реализован вариант отдельных физических JAM для явно назначенных Link-поинтов
своего нодового AKA. [Проектные решения](../openspec/changes/add-point-netmail-mailboxes/design.md)
и [эксперименты HPT](../openspec/changes/add-point-netmail-mailboxes/research/hpt-routing.md)
содержат обоснование выбора. Рабочее включение выполняется отдельно после согласования.

- HPT toss принимает почту в ingress; FFIDO распределяет её по полному адресу.
  Общая NetmailArea босса не открывается поинтам.
- Личный ящик не зарегистрирован в HPT и хранит входящие/исходящие. Egress JAM служит
  транспортом; HPT pack не удаляет пользовательскую историю.
- Source-key и адресный delivery-key, Locked claim, журнал append и SQLite provenance/outbox
  позволяют восстанавливать переходы. Имена и один флаг Private не определяют владельца.
- Телефон и ноутбук имеют отдельные сессии одного профиля и общее серверное состояние.
  Локальный HPT им не нужен. Push, общие черновики и точная прокрутка не включены.
- Owner-роль не даёт доступ к чужому mailbox endpoint; файловый администратор хоста
  по-прежнему может читать базы. Криптографической тайны от администратора нет.
- Доставка между управляемыми поинтами выполняется локально. Отправка наружу подтверждает
  сначала только сохранение. Неопределённость HPT pack блокирует повтор до сверки оператором.

[Настройка, проверки, backup и rollback](ftn-check.md#полный-временный-цикл-персональной-почты).
Временные тесты не редактируют рабочую инфраструктуру HPT.

Carbon-подборки публичных эх сохраняют ACL источника; CarbonTo по имени не является
личным ящиком. Закрытая групповая эха остаётся EchoArea со своим списком линков.
Squish, вложения и управление служебными роботами в этот режим не входят.
