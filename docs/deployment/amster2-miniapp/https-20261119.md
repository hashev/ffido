## Поведение продления

Общий существующий `/home/yurik/fido/ffido/maintenance.lock`, EX/NB flock через
read-only FD. При занятости exit75, без Certbot и изменения файлов.
Certbot закреплён registry digest, обслуживается только production cert-name;
standalone HTTP-01 на80→8081, native renew03:13/15:13 остаётся независимым.
Сохраняются отдельные ключ/аккаунт. Ошибки не игнорируются; следующий запуск повторит попытку.

Перед установкой: материализация ссылок только из production archive, проверка срока,
совпадения public key, доверенной цепочки/hostname, Envoy validate в network=none
с новым сертификатом и настоящим backend CA. Если файлы не изменились, действий с
контейнером нет. Если gateway отсутствует либо остановлен, обновляются только файлы;
скрипт НЕ создаёт и НЕ запускает его.

После будущего разрешённого запуска gateway: при новом сертификате скрипт проверяет
pinned image, сохраняет `certs/previous` (root0700/key0600), останавливает только этот
контейнер, устанавливает оба файла, запускает только ранее работавший gateway.
Проверяет локальный HTTPS без -k, CORS preflight и fingerprint реально выдаваемого
сертификата. При ошибке возвращает прежнюю пару и запускает прежний gateway.
Два rename при работающем читателе не считаются атомарной установкой пары.
Backend/tosser/fido/jamnntpd этот скрипт не управляет.

Операционные журналы: `logs/renew.log`, максимум1MiB ×4 с ротацией;
`logs/last-command.private.log` — последние приватные diagnostics при ошибке команды.
Ключи, account state и private logs не копировать в Git/Pages.
