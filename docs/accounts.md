# Имя аккаунта и повторный вход

Имя отправителя FFIDO берёт из серверного профиля FTN-адреса. Первый успешный
Login создаёт этот профиль, последующие входы с другим именем сохраняют прежнюю
идентичность и её личные данные. Изменение поля имени в клиенте не переименовывает
существующий аккаунт. Не создавайте production-аккаунт диагностическим входом с
фиктивным именем; испытания регистрации и отправки выполняйте на изолированных базах.

На amster2 первый диагностический вход адреса `2:5015/120` создал имя
`Deployment verification`. Оно исправлено на `Yuriy Khashev` адресной транзакцией
SQLite после согласованного backup метаданных. User ID, FTN-адрес, сессии,
история и закладки сохранены; хэши 448 JAM-файлов не менялись. Старые сообщения
не переименовывались. Клиент с уже открытым профилем увидит новое имя после
перезапуска с восстановлением сессии или повторного подключения.

Для аналогичного исправления оператор сначала делает backup SQLite через
backup API при работающем WAL либо после остановки всех писателей. Затем в
транзакции меняет только `users.name` у точно проверенного FTN-адреса и
проверяет число изменённых строк (одна). Запрещено удалять аккаунт, пересоздавать
metadata.db или менять user_id/FTN-адрес ради имени: это нарушит привязку личных
данных. При неуспехе транзакцию откатить; старые JAM не восстанавливать из backup.
Пароли, ключи сессий, токены и metadata.db в Git не добавлять.

Нативные клиенты сохраняют сессию и пароль HPT в системном защищённом хранилище.
После успешного входа пароль доступен только тому же серверу, FTN-адресу и
локальному профилю; поле скрыто. Истечение сессии сохраняет пароль для ручного
повторного подключения. Смена пароля на сервере требует ввода нового значения.
Явный выход удаляет оба секрета; при сбое удаления приложение блокирует их
повторное использование. Web пароль не сохраняет. При недоступном хранилище
можно войти вручную; plaintext fallback отсутствует.
