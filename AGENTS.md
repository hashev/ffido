# Разработка FFIDO

- Отвечайте на русском. Сохраняйте пользовательские изменения и делайте только необходимые правки.
- `apps/frontend/` — существующее Flutter-приложение; его зависимости и команды выполняются из этой папки.
- `apps/backend/` — существующий сервер C++23. Для сборки используйте корневой CMake-проект: он включает бэкенд и регистрирует его тесты.
- `openspec/` в корне — единый источник спецификаций и изменений для обоих компонентов. Не создавайте отдельные корни OpenSpec в приложениях.
- Перед изменением читайте соответствующие спецификации, код, тесты и документацию компонента. Для нового запланированного изменения используйте OpenSpec propose, затем apply; archive — после реализации и проверок.
- При изменении общего HTTP-контракта учитывайте обе стороны. Перенос в монорепозиторий сам по себе не означает, что клиент и сервер уже интегрированы.
- Пишите новые артефакты OpenSpec на русском. Существующие архивы сохраняйте как исторические документы: относительные пути в старом архиве относятся к прежнему корню клиента.
- Сохраняйте текущие технологии и версии зависимостей. Не выполняйте попутных рефакторингов, обновлений toolchain или изменений протокола.
- Не добавляйте в Git локальный `apps/backend/config.json`, FTN-базы, SQLite-файлы, uploads, секреты и сборочные кеши.

Проверки клиента:

```sh
cd apps/frontend
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
```

Сборка и проверки бэкенда из корня:

```sh
cmake -S . -B build/backend -DCMAKE_BUILD_TYPE=Debug
cmake --build build/backend --parallel 4
ctest --test-dir build/backend --output-on-failure
```

После изменений проверяйте итоговый diff. Сообщайте, что проверено, и явно указывайте оставшиеся ограничения. Не коммитьте и не публикуйте изменения без отдельного запроса.
