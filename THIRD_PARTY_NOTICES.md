# Сторонние компоненты

MIT в корне относится к собственному коду FFIDO, а не перелицензирует зависимости.
Сохраняйте copyright и лицензии в составе исходников и пакетов.

| Компонент | Лицензия / источник |
| --- | --- |
| Flutter / Dart | BSD-style; лицензии SDK и плагинов в клиентском пакете |
| gRPC / Protobuf / Abseil | Apache-2.0 / BSD-3-Clause / Apache-2.0, соответственно; см. закреплённые исходники |
| spdlog | MIT |
| nlohmann/json | MIT |
| SQLite | public domain; встроенные заголовки сохранены |
| OpenSSL | Apache-2.0 для используемой ветки 3.x |
| c-ares / RE2 / zlib | соответствующие лицензии включаются из dependency prefix |
| Husky fidoconf | GNU Library GPL 2 или более поздняя версия, согласно заголовкам исходников |
| Husky huskylib / SMAPI | GNU LGPL; точные тексты — COPYING закреплённых исходников |

Backend статически включает libfidoconfig с локальным адаптером `cfg.c`.
Исходная ревизия и SHA-256 проверяются в `cmake/FidoConfigAdapter.cmake`;
изменения — `cmake/patches/fidoconfig-open.patch`. Сохраняйте исходные notices.

Backend-пакеты должны содержать `share/ffido/legal/` и
`share/ffido/relink/`: закреплённые исходники включённых зависимостей,
тексты лицензий, объектные файлы FFIDO и библиотеки/команды перелинковки.
Это позволяет собрать/перелинковать программу с изменённой библиотекой Husky.
Не удаляйте этот комплект при перепаковке. Замена библиотеки пользователем
не ограничивается дополнительными условиями MIT. Системные библиотеки ОС
не входят в распространяемый архив.

Клиентские пакеты включают тексты лицензий пакетов из Dart package_config,
а Flutter также формирует свой реестр лицензий. Собственный MIT notice
дополнительно встроен в клиент как assets/legal/LICENSE; тест требует
побайтового совпадения с корневым LICENSE. Наличие записи в таблице
не заменяет фактические тексты лицензий в дистрибутиве. Упаковщик отказывается
выпускать backend без комплекта relink и legal.
